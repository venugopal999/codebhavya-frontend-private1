PLACEMENT · LEVEL 22</p><h1>Modern Java &amp; Date/Time</h1><p class="lead">Use enums, records, sealed hierarchies, pattern variables and immutable java.time types to model modern domain data.</p><div class="lesson-meta"><span>Level 22 of 24</span><span>Intermediate</span><span>110–150 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Apply modern Java features where they strengthen the model</h2><ul><li>Design enum behaviour.</li><li>Use records as value carriers.</li><li>Restrict hierarchies with sealed types.</li><li>Use pattern variables.</li><li>Handle time zones and durations correctly.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#trace">Trace</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Modern Java &amp; Date/Time: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. Enums, records and sealed types</h3><p>An enum defines a closed set of instances and can hold fields and behaviour. A record declares a transparent shallowly immutable data carrier with generated accessors, equality, hash and text form.</p><p>A sealed type lists permitted direct subtypes, making a domain hierarchy intentionally closed while each subtype is final, sealed or non-sealed.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Feature</th><th>Use</th><th>Do not assume</th></tr></thead><tbody><tr><td>enum</td><td>Closed named instances</td><td>Just an integer</td></tr><tr><td>record</td><td>Value-oriented carrier</td><td>Deep immutability</td></tr><tr><td>sealed</td><td>Closed subtype family</td><td>No future evolution</td></tr><tr><td>pattern variable</td><td>Type test plus binding</td><td>General polymorphism replacement</td></tr></tbody></table></div></article><article class="concept-block"><h3>2. Pattern variables and switch</h3><p><code>instanceof Type name</code> combines a type test with a variable scoped where the test is true. It removes a redundant cast.</p><p>Modern switch expressions yield values and can be exhaustive over enums. Later Java versions add more pattern-switch capabilities; compile against the version your deployment actually uses.</p></article><article class="concept-block"><h3>3. Date/time types</h3><p>Instant is a UTC timeline point; LocalDate is a calendar date without time or zone; LocalDateTime still has no zone; ZonedDateTime applies regional offset rules.</p><p>Duration measures seconds/nanos, while Period measures calendar years/months/days. Convert between local values and instants only with an explicit ZoneId.</p><div class="concept-note"><strong>Important:</strong> Store an Instant for a global event and retain a ZoneId when future local scheduling semantics matter.</div></article><article class="concept-block"><h3>4. Immutability and version awareness</h3><p>java.time values are immutable and thread-safe. Every adjustment returns a new value.</p><p>Java evolves on a six-month release cadence with long-term-support releases chosen by vendors. Keep source/target version, runtime version and feature use aligned.</p></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Record with compact validation</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    record Range(int start,int end){
        Range{if(start&gt;end)throw new IllegalArgumentException(&quot;start after end&quot;);}
        int length(){return end-start;}
    }
    public static void main(String[] args){System.out.println(new Range(3,8).length());}
}</code></pre></div><footer>The compact constructor validates components before assignment and the derived operation belongs with the value.<pre>Output:
5</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Resolve a regional time</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>import java.time.*;
public class Program {
    public static void main(String[] args){
        LocalDate date=LocalDate.of(2026,9,11);

        System.out.println(start.toInstant());
    }
}</code></pre></div><footer>A local meeting time becomes a global Instant only after applying an explicit region and its offset rules.<pre>Output:

Are records deeply immutable?</summary><p>No. Component fields are final, but a component may reference a mutable object. Make defensive copies for deep immutability.</p></details><details><summary>2. Instant versus LocalDateTime?</summary><p>Instant identifies a UTC timeline point; LocalDateTime is a wall-clock value without zone or offset.</p></details><details><summary>3. Period versus Duration?</summary><p>Period uses calendar units such as months and days; Duration uses exact elapsed seconds and nanoseconds.</p></details><details><summary>4. Why sealed classes?</summary><p>They make a finite domain hierarchy explicit and let compilers/tools reason about permitted variants.</p></details><details><summary>5. Enum versus constants?</summary><p>Enums provide type safety, one canonical instance per value, switch support and attached behaviour.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
