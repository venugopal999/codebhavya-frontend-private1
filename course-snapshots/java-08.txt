OBJECT-ORIENTED DESIGN · LEVEL 08</p><h1>Methods, Overloading &amp; Recursion</h1><p class="lead">Design small contracts, understand Java&#39;s value-passing rule, resolve overloads and trace recursive call frames.</p><div class="lesson-meta"><span>Level 8 of 24</span><span>Intermediate</span><span>110–150 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Decompose algorithms into clear method contracts</h2><ul><li>Define parameters, returns and preconditions.</li><li>Explain pass-by-value.</li><li>Use overloading without ambiguity.</li><li>Trace recursion frames.</li><li>Choose iteration or recursion deliberately.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#trace">Trace</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Methods, Overloading &amp; Recursion: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. Method contracts</h3><p>A method contract states accepted input, returned result, side effects and failure policy. A focused method has one reason to change and can be tested independently.</p><p>Parameters are local variables initialized from argument values. Return exits the current call and may provide a compatible value.</p></article><article class="concept-block"><h3>2. Java is pass-by-value</h3><p>Every argument value is copied. For an object, that value is a reference; the method can mutate the referenced object but cannot replace the caller&#39;s variable.</p><p>This single rule explains why primitive reassignment is invisible while an array element mutation is visible.</p><div class="concept-note"><strong>Important:</strong> Pass-by-reference is not Java&#39;s parameter mechanism.</div></article><article class="concept-block"><h3>3. Overloading</h3><p>Overloads share a name but differ in parameter lists. Resolution happens at compile time from declared argument types and applicable conversions.</p><p>Return type alone cannot distinguish overloads. Avoid overload families where null or numeric promotion makes the intended target unclear.</p></article><article class="concept-block"><h3>4. Recursion and frames</h3><p>Each recursive call gets its own parameters and locals on a call stack. A base case returns directly; the recursive case reduces the problem toward it.</p><p>Recursion expresses trees and divide-and-conquer naturally, but deep linear recursion can overflow the stack because Java does not guarantee tail-call elimination.</p></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>A validated method</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    static double average(int total,int count){
        if(count&lt;=0) throw new IllegalArgumentException(&quot;count must be positive&quot;);
        return total/(double)count;
    }
    public static void main(String[] args){
        System.out.println(average(17,4));
    }
}</code></pre></div><footer>The precondition is enforced at the boundary and the cast belongs inside the reusable abstraction.<pre>Output:
4.25</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Recursive digit sum</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    static int digitSum(int n){
        n=Math.abs(n);
        if(n&lt;10) return n;
        return n%10+digitSum(n/10);
    }
    public static void main(String[] args){System.out.println(digitSum(5304));}
}</code></pre></div><footer>Each call removes one digit, so the non-negative argument strictly approaches the base case.<pre>Output:
12</pre></footer></article></section><section class="lesson-section" id="trace"><header class="section-heading"><span>INTERACTIVE LEARNING · PROGRAM TRACE</span><h2>Trace recursive call frames</h2><p>Calls descend first; additions complete while frames return.</p></header><div class="visualizer"><div class="trace-code"><header>JAVA EXECUTION</header><div class="trace-lines" id="traceLines"><div class="trace-line" data-line="1"><b>1</b><span>sum(530)</span></div><div class="trace-line" data-line="2"><b>2</b><span>return 0 + sum(53)</span></div><div class="trace-line" data-line="3"><b>3</b><span>return 3 + sum(5)</span></div><div class="trace-line" data-line="4"><b>4</b><span>base: return 5</span></div><div class="trace-line" data-line="5"><b>5</b><span>sum(53) returns 8</span></div><div class="trace-line" data-line="6"><b>6</b><span>sum(530) returns 8</span></div></div></div><div class="trace-state"><header>VISIBLE RUNTIME STATE</header><div class="trace-stage"><span id="traceCounter">READY</span><h3 id="traceTitle">Start the trace</h3><p id="traceText">Move line by line and connect the Java statement to its runtime effect.</p><div class="state-box" id="traceState">No state change yet.</div></div><div class="trace-controls"><button id="traceNext">Next step →</button><button id="traceAuto">▶ Auto run</button><button id="traceReset">Reset</button></div></div></div></section><section class="lesson-section" id="revision"><header class="section-heading"><span>QUICK REVISION</span><h2>Recall the Essential Ideas</h2></header><div class="revision-grid"><div><b>01</b> A contract documents input, output and side effects.</div><div><b>02</b> Java always copies argument values.</div><div><b>03</b> Object references are values too.</div><div><b>04</b> Return type alone cannot overload.</div><div><b>05</b> Recursion needs a base case and progress.</div><div><b>06</b> Each call owns a stack frame.</div></div></section><section class="lesson-section" id="interview"><header class="section-heading"><span>INTERVIEW QUESTIONS</span><h2>Explain, Do Not Memorize</h2><p>Open each answer only after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. Is Java pass-by-reference?</summary><p>No. It passes copies of values; an object argument value happens to be a reference.</p></details><details><summary>2. Can methods overload by return type?</summary><p>No, because a call without assignment would not identify which overload to choose.</p></details><details><summary>3. Overloading versus overriding?</summary><p>Overloading selects signatures at compile time; overriding supplies subtype behaviour chosen dynamically.</p></details><details><summary>4. What causes StackOverflowError?</summary><p>Too many nested calls, commonly recursion without termination or recursion deeper than available stack.</p></details><details><summary>5. When prefer recursion?</summary><p>When the data or algorithm is naturally recursive and depth is safely bounded; otherwise iteration may be clearer and safer.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
