CORE LIBRARIES · LEVEL 17</p><h1>Lambdas &amp; Functional Interfaces</h1><p class="lead">Treat behaviour as data with target-typed lambdas, method references and small functional contracts.</p><div class="lesson-meta"><span>Level 17 of 24</span><span>Intermediate</span><span>110–150 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Pass behaviour without obscuring intent</h2><ul><li>Recognize functional interfaces.</li><li>Write lambdas and method references.</li><li>Use Predicate/Function/Consumer/Supplier.</li><li>Understand capture rules.</li><li>Compose side-effect-light behaviour.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Lambdas &amp; Functional Interfaces: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. Target typing</h3><p>A lambda has no standalone nominal type; its target functional interface supplies parameter and return types. A functional interface has one abstract method, though it may also have defaults.</p><p>Use <code>@FunctionalInterface</code> to have the compiler protect the intended contract.</p></article><article class="concept-block"><h3>2. Core function shapes</h3><p>Predicate tests, Function transforms, Consumer performs an effect and Supplier creates or provides a value. Primitive specializations avoid boxing on hot numeric paths.</p><p>Method references are alternate syntax when an existing method exactly matches the target shape.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Interface</th><th>Shape</th><th>Example</th></tr></thead><tbody><tr><td>Predicate&lt;T&gt;</td><td>T → boolean</td><td>validation</td></tr><tr><td>Function&lt;T,R&gt;</td><td>T → R</td><td>mapping</td></tr><tr><td>Consumer&lt;T&gt;</td><td>T → void</td><td>logging/output</td></tr><tr><td>Supplier&lt;T&gt;</td><td>() → T</td><td>lazy creation</td></tr></tbody></table></div></article><article class="concept-block"><h3>3. Capture and effects</h3><p>Lambdas may capture local variables only when final or effectively final. The restriction avoids confusing mutable stack capture.</p><p>A lambda can still mutate referenced objects, but hidden side effects make composition and parallel execution harder to reason about.</p><div class="concept-note"><strong>Important:</strong> Name business rules as functions; do not compress complex logic merely to make a one-line lambda.</div></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Compose validation</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>import java.util.function.Predicate;
public class Program {
    public static void main(String[] args){
        Predicate&lt;String&gt; present=s-&gt;s!=null&amp;&amp;!s.isBlank();
        Predicate&lt;String&gt; shortEnough=s-&gt;s.length()&lt;=12;
        System.out.println(present.and(shortEnough).test(&quot;CodeBhavya&quot;));
    }
}</code></pre></div><footer>Short-circuit composition applies the length rule only after the value is known present.<pre>Output:
true</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Pass an ordering policy</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>import java.util.*;
public class Program {
    public static void main(String[] args){List&lt;String&gt; names=new ArrayList&lt;&gt;(List.of(&quot;Java&quot;,&quot;C&quot;,&quot;Python&quot;));names.sort(Comparator.comparingInt(String::length).thenComparing(String::compareTo));System.out.println(names);}
}</code></pre></div><footer>Method references expose existing operations and the comparator includes a deterministic tie-break.<pre>Output:
[C, Java, Python]</pre></footer></article></section><section class="lesson-section" id="revision"><header class="section-heading"><span>QUICK REVISION</span><h2>Recall the Essential Ideas</h2></header><div class="revision-grid"><div><b>01</b> A lambda needs a target functional interface.</div><div><b>02</b> Functional means one abstract method.</div><div><b>03</b> Predicates test; Functions transform.</div><div><b>04</b> Consumers cause effects; Suppliers provide.</div><div><b>05</b> Captured locals must be effectively final.</div><div><b>06</b> Pure functions compose more safely.</div></div></section><section class="lesson-section" id="interview"><header class="section-heading"><span>INTERVIEW QUESTIONS</span><h2>Explain, Do Not Memorize</h2><p>Open each answer only after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. What is a functional interface?</summary><p>An interface with one abstract method, usable as a lambda target; Object methods and defaults do not add to that count.</p></details><details><summary>2. Why effectively final capture?</summary><p>Local variables live in stack frames; copying a stable value into the lambda avoids mutable-local lifetime ambiguity.</p></details><details><summary>3. Lambda versus anonymous class?</summary><p>A lambda implements functional behaviour with lexical this; an anonymous class creates a distinct object scope and can implement more structure.</p></details><details><summary>4. What is a method reference?</summary><p>Compact syntax for a lambda that only invokes an existing compatible method.</p></details><details><summary>5. Why avoid side effects?</summary><p>They make ordering, reuse, testing and parallel reasoning harder.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
