class="lesson-section interview-section"><p class="section-label">PLACEMENT & INTERVIEW</p><h2>Explain the concept, don't just memorize it</h2><div class="interview-list"><details class="interview-item"><summary><span>01</span>What is deployment?</summary><div class="interview-answer"><p>Deployment is the process of releasing an application to an environment where it can run and serve users.</p></div></details><details class="interview-item"><summary><span>02</span>Why is production different from development?</summary><div class="interview-answer"><p>Production serves real users and therefore requires stronger security, reliability, monitoring, configuration and recovery practices.</p></div></details><details class="interview-item"><summary><span>03</span>Why should frontend and backend configuration be separated from source code?</summary><div class="interview-answer"><p>Different environments require different values, and separating configuration avoids hard-coding deployment-specific settings.</p></div></details><details class="interview-item"><summary><span>04</span>Why should secrets not be committed to Git?</summary><div class="interview-answer"><p>Repository contents can be copied or exposed, so sensitive credentials should be stored in protected environment configuration.</p></div></details><details class="interview-item"><summary><span>05</span>Why is HTTPS important?</summary><div class="interview-answer"><p>HTTPS protects communication between clients and servers by encrypting data in transit.</p></div></details><details class="interview-item"><summary><span>06</span>What is observability?</summary><div class="interview-answer"><p>Observability is the ability to understand system behavior using signals such as logs, metrics and traces.</p></div></details><details class="interview-item"><summary><span>07</span>What is the difference between logs and metrics?</summary><div class="interview-answer"><p>Logs record individual events or messages, while metrics provide numerical measurements that reveal system patterns.</p></div></details><details class="interview-item"><summary><span>08</span>What is a health check?</summary><div class="interview-answer"><p>A health check provides a simple way to determine whether a service or dependency is functioning.</p></div></details><details class="interview-item"><summary><span>09</span>What is the difference between liveness and readiness?</summary><div class="interview-answer"><p>Liveness generally indicates that a process is running, while readiness indicates that the service is prepared to receive traffic.</p></div></details><details class="interview-item"><summary><span>10</span>Why are production backups necessary?</summary><div class="interview-answer"><p>Backups provide a recovery path when data is lost, corrupted or otherwise unavailable.</p></div></details><details recovery.</p></div></details><details class="interview-item"><summary><span>12</span>What should a production log avoid?</summary><div class="interview-answer"><p>Logs should avoid exposing passwords, authentication tokens and other sensitive information.</p></div></details><details class="interview-item"><summary><span>13</span>What is CI/CD?</summary><div class="interview-answer"><p>CI/CD connects automated code validation with repeatable software delivery and deployment workflows.</p></div></details><details class="interview-item"><summary><span>14</span>Why should production alerts be actionable?</summary><div class="interview-answer"><p>Too many irrelevant alerts create noise and can cause important failures to be ignored.</p></div></details><details class="interview-item"><summary><span>15</span>What is incident response?</summary><div class="interview-answer"><p>Incident response is the structured process of detecting, assessing, stabilizing,
