01</p><h2>What are we actually learning?</h2></div></div><p class="concept-intro">Before writing a single line of HTML, CSS or JavaScript, you need to understand the environment in which web applications work.</p><div class="explanation-list"><p>When you open a website, it may look like a single page on your screen. Internally, however, many systems cooperate to produce that page.</p><p>Your device runs a browser. The browser communicates with remote systems through the Internet. A domain name is resolved to an IP address. The browser sends requests to a server. The server sends responses containing resources such as HTML, CSS, JavaScript, images and other data.</p><p>Understanding this complete chain will make later MERN topics much easier. When you eventually learn Express, REST APIs, React and MongoDB, you will already understand where each technology fits.</p></div><div class="key-idea"><span>💡</span><div><strong>Key Idea</strong><p>MERN development becomes much easier when you understand the complete journey of data before learning individual technologies.</p></div></div></section><section class="lesson-section concept-section"><div class="concept-heading"><div class="concept-number">02</div><div><p class="section-label">CONCEPT 02</p><h2>Internet vs World Wide Web</h2></div></div><p class="concept-intro">These two terms are often used as if they mean the same thing, but they are not the same.</p><div class="explanation-list"><p>The Internet is the global network infrastructure that allows computers and devices to communicate with each other.</p><p>The World Wide Web is one service that operates on top of that infrastructure. Websites and web applications use technologies such as URLs, HTTP, HTML, CSS and JavaScript to operate on the Web.</p><p>Other services can also use the Internet. Email, online gaming, file transfer and many other systems are not simply the World Wide Web.</p></div><div class="real-example"><strong>🌍 REAL-WORLD EXAMPLE</strong><p>Think of the Internet as the road network and the Web as one major transportation service using those roads.</p></div><div class="comparison-table"><table><thead><tr><th>Term</th><th>Meaning</th></tr></thead><tbody><tr><td><strong>Internet</strong></td><td>The global network of interconnected systems.</td></tr><tr><td><strong>Web</strong></td><td>A system of linked resources and applications accessed through web technologies.</td></tr></tbody></table></div></section><section class="lesson-section concept-section"><div class="concept-heading"><div class="concept-number">03</div><div><p class="section-label">CONCEPT 03</p><h2>Client and Server</h2></div></div><p class="concept-intro">The client-server model is one of the most important ideas in web development.</p><div class="explanation-list"><p>A client is the system that requests a resource or service. In normal web browsing, the browser is the client.</p><p>A server is a system that receives requests, processes them and sends responses.</p><p>The client and server can be physically far apart. They communicate through networks using defined protocols.</p></div><div class="real-example"><strong>🌍 REAL-WORLD EXAMPLE</strong><p>When you open codebhavya.com, your browser acts as the client and the web infrastructure serving CodeBhavya provides the requested resources.</p></div><div class="learning-flow"><h3>Step-by-Step Flow</h3><div class="flow-track"><div class="flow-item"><div class="section-label">CONCEPT 04</p><h2>What is a Browser?</h2></div></div><p class="concept-intro">A browser is much more than an application that displays websites.</p><div class="explanation-list"><p>A browser understands web technologies and provides the environment in which web pages execute.</p><p>It sends network requests, receives resources, parses HTML, builds the DOM, applies CSS, executes JavaScript and displays the resulting interface.</p><p>Browsers also provide developer tools that allow developers to inspect HTML, CSS, JavaScript, network requests, storage and runtime problems.</p></div><div class="key-idea"><span>💡</span><div><strong>Key Idea</strong><p>The browser is both a network client and an execution environment for web applications.</p></div></div><div class="real-example"><strong>🌍 REAL-WORLD EXAMPLE</strong><p>Google Chrome</p></div><div class="real-example"><strong>🌍 REAL-WORLD EXAMPLE</strong><p>Mozilla EXAMPLE</strong><p>Safari</p></div></section><section class="lesson-section concept-section"><div class="concept-heading"><div class="concept-number">05</div><div><p class="section-label">CONCEPT 05</p><h2>What is a Server?</h2></div></div><p class="concept-intro">A server is a system that provides resources or services to clients.</p><div class="explanation-list"><p>A web server may receive an HTTP request and return an HTML page, an image, a JavaScript file or other resource.</p><p>In modern applications, the server may also execute application logic, authenticate users, validate data, communicate with databases and return JSON responses.</p><p>A production application may use several different servers or services rather than one physical machine.</p></div><div class="info-list"><h3>Server Responsibilities</h3><ul><li>Receive requests</li><li>Process application logic</li><li>Read or modify data</li><li>Communicate with databases</li><li>Authenticate class="concept-number">06</div><div><p class="section-label">CONCEPT 06</p><h2>IP Addresses</h2></div></div><p class="concept-intro">Computers communicate using network addresses. One important type is the IP address.</p><div class="explanation-list"><p>An IP address identifies a network interface in an IP network.</p><p>Humans generally prefer names such as codebhavya.com rather than remembering numerical network addresses.</p><p>DNS provides the naming system that helps map domain names to IP addresses.</p></div><div class="warning-box"><span>⚠️</span><div><strong>Important</strong><p>An IP address identifies a network endpoint, but it should not be treated as a permanent identity for a website. Ports help identify the destination service associated with network traffic.</p><div class="explanation-list"><p>An IP address helps identify a network endpoint, while a port identifies a service endpoint on that host.</p><p>Common web-related ports include 80 for HTTP and 443 for HTTPS.</p><p>Developers also frequently run local applications on ports such as 3000, 5000, 5173 or 8000.</p></div><div class="key-idea"><span>💡</span><div><strong>Key Idea</strong><p>localhost identifies your own machine; the port identifies the service endpoint your application is listening on.</p></div></div><div class="real-example"><strong>🌍 REAL-WORLD EXAMPLE</strong><p>http://localhost:3000</p></div><div class="real-example"><strong>🌍 REAL-WORLD EXAMPLE</strong><p>http://localhost:5000</p></div><div class="real-example"><strong>🌍 REAL-WORLD EXAMPLE</strong><p>https://example.com:443</p></div></section><section class="lesson-section concept-section"><div class="concept-heading"><div class="concept-number">11</div><div><p class="section-label">CONCEPT 11</p><h2>Packets and Data on the Network</h2></div></div><p class="concept-intro">Data sent over networks is transported through networking mechanisms that break communication into manageable units.</p><div class="explanation-list"><p>At a beginner level, think of network communication as data being carried across a network through packets.</p><p>Packets contain information needed for delivery and are processed by networking equipment and protocols.</p><p>You do not need to become a network engineer to learn MERN, but understanding that your HTTP communication travels through networking layers helps explain latency, failures and debugging.</p></div><div class="warning-box"><span>⚠️</span><div><strong>Important</strong><p>Do not imagine the Internet as one direct cable between your browser and a server.
