PLACEMENT · LEVEL 23</p><h1>JDBC &amp; Database Programming</h1><p class="lead">Execute parameterized SQL, map rows deliberately and manage transaction and connection lifecycles.</p><div class="lesson-meta"><span>Level 23 of 24</span><span>Advanced</span><span>160–220 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Build safe transactional database boundaries</h2><ul><li>Use JDBC resource hierarchy.</li><li>Prevent SQL injection.</li><li>Map ResultSet correctly.</li><li>Control commit and rollback.</li><li>Understand pooling and isolation.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#trace">Trace</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>JDBC &amp; Database Programming: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. JDBC lifecycle</h3><p>A DataSource or DriverManager supplies a Connection. PreparedStatement carries parameterized SQL, and ResultSet exposes a cursor positioned before the first row.</p><p>Close result sets, statements and connections deterministically. In pooled systems, closing a connection returns it to the pool.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Resource</th><th>Responsibility</th><th>Lifetime</th></tr></thead><tbody><tr><td>Connection</td><td>Session/transaction</td><td>Unit of work</td></tr><tr><td>PreparedStatement</td><td>Compiled SQL plus parameters</td><td>Operation</td></tr><tr><td>ResultSet</td><td>Row cursor</td><td>While reading result</td></tr><tr><td>DataSource</td><td>Connection provider/pool</td><td>Application</td></tr></tbody></table></div></article><article class="concept-block"><h3>2. Parameters and mapping</h3><p>Prepared statements keep SQL structure separate from data and prevent injection through parameter values. They do not parameterize table or column identifiers; whitelist identifiers if dynamic selection is unavoidable.</p><p>Read columns by stable labels, handle SQL NULL explicitly and map rows to domain values at the repository boundary.</p></article><article class="concept-block"><h3>3. Transactions</h3><p>With auto-commit disabled, a connection groups statements until commit or rollback. Every failure path must roll back before the connection is reused.</p><p>Keep transactions short and avoid remote calls while holding locks. Isolation determines which concurrent anomalies are permitted and has performance trade-offs.</p><div class="concept-note"><strong>Important:</strong> Money transfers require one transaction containing both balance changes and invariant checks.</div></article><article class="concept-block"><h3>4. Pooling and production concerns</h3><p>Opening physical database connections is expensive, so applications use bounded pools with timeouts and health checks.</p><p>Observe query latency, pool saturation and slow SQL; add indexes from measured query plans rather than guesswork.</p></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Parameterized lookup structure</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>import java.sql.*;
public class Program {
    static void find(Connection connection,int id) throws SQLException{
        String sql=&quot;select id, name from student where id = ?&quot;;
        try(PreparedStatement ps=connection.prepareStatement(sql)){
            ps.setInt(1,id);
            try(ResultSet rs=ps.executeQuery()){
                while(rs.next())System.out.println(rs.getInt(&quot;id&quot;)+&quot; &quot;+rs.getString(&quot;name&quot;));
            }
        }
    }
    public static void main(String[] args){System.out.println(&quot;Repository method compiles; supply a configured connection.&quot;);}
}</code></pre></div><footer>The id is bound as data, resources nest by ownership, and mapping uses explicit labels.<pre>Output:
Repository method compiles; supply a configured connection.</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Transaction template</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>import java.sql.*;
public class Program {
    static void transfer(Connection c) throws SQLException{
        boolean old=c.getAutoCommit();c.setAutoCommit(false);
        try(PreparedStatement p=c.prepareStatement(&quot;update account set balance=balance-? where id=?&quot;)){
            p.setLong(1,500);p.setInt(2,1);p.executeUpdate();
            c.commit();
        }catch(SQLException e){c.rollback();throw e;}
        finally{c.setAutoCommit(old);}
    }
    public static void main(String[] args){System.out.println(&quot;Transaction boundary ready&quot;);}
}</code></pre></div><footer>The template demonstrates rollback and connection-state restoration; a real transfer must also credit the destination and enforce affected-row/invariant checks.<pre>Output:
Transaction boundary ready</pre></footer></article></section><section class="lesson-section" id="trace"><header class="section-heading"><span>INTERACTIVE LEARNING · PROGRAM TRACE</span><h2>Trace a after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. Statement versus PreparedStatement?</summary><p>PreparedStatement binds typed values separately, improves safety and may support plan reuse; Statement concatenation is injection-prone.</p></details><details><summary>2. What is auto-commit?</summary><p>When enabled, each statement commits as its own transaction. Disable it for multi-statement atomic units.</p></details><details><summary>3. What does ResultSet.next do?</summary><p>Moves the cursor to the next row and reports whether a row exists; no getters are valid before the first successful next.</p></details><details><summary>4. Why connection pooling?</summary><p>It reuses expensive physical connections, bounds concurrency and reduces acquisition latency.</p></details><details><summary>5. What is transaction isolation?</summary><p>A database contract controlling which effects of concurrent transactions can be observed, trading anomalies against concurrency.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
