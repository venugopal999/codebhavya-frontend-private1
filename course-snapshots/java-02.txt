Input</h1><p class="lead">Model information with the right type, understand how primitive values differ from object references, convert deliberately and read user input without Scanner surprises.</p><div class="lesson-meta"><span>Level 2 of 24</span><span>Beginner</span><span>110–140 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Choose safe types and trace value changes</h2><ul><li>Declare, initialize and update variables.</li><li>Choose among Java&#39;s eight primitive types.</li><li>Explain widening, narrowing and numeric promotion.</li><li>Distinguish primitive values from references.</li><li>Read tokens and complete lines safely with Scanner.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#trace">Trace</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Give Every Value a Clear Meaning and Valid Range</h2><p>A variable is a named storage location governed by a declared type. Type choice affects range, precision, operations and the errors the compiler can prevent.</p></header><article class="concept-block"><h3>1. Declaration, initialization and scope</h3><p>A declaration introduces a name and type; initialization supplies the first value. Local variables must be definitely assigned before use. Fields receive default values, but relying on defaults can hide incomplete object construction.</p><p>Scope is the source region where a name is visible. A variable declared inside a block cannot be used outside it. Prefer the narrowest useful scope so state is easier to understand.</p><ul><li>Use descriptive camelCase names such as <code>totalMarks</code>.</li><li>Constants use <code>static final</code> and usually UPPER_SNAKE_CASE.</li><li>Do not reuse one variable for unrelated meanings.</li></ul><div class="concept-note"><strong>Important:</strong> <code>var</code> performs local type inference; Java remains statically typed. It cannot be used for fields, method parameters or an uninitialized local.</div></article><article class="concept-block"><h3>2. Primitive types and literals</h3><p>Java has eight primitive types: byte, short, int, long, float, double, char and boolean. Integral types have specified two&#39;s-complement widths. Floating-point values follow IEEE 754 and cannot exactly represent every decimal fraction.</p><p>Integer literals are <code>int</code> unless suffixed with <code>L</code> when necessary. Decimal literals are <code>double</code> unless suffixed with <code>F</code>. Underscores can improve readability but cannot appear at arbitrary literal boundaries.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Type</th><th>Typical use</th><th>Key caution</th></tr></thead><tbody><tr><td>int / long</td><td>Counts and whole-number ranges</td><td>Overflow wraps; choose range deliberately</td></tr><tr><td>double</td><td>Measurements and scientific calculations</td><td>Binary floating point is approximate</td></tr><tr><td>char</td><td>One UTF-16 code unit</td><td>Not always a complete Unicode character</td></tr><tr><td>boolean</td><td>True/false condition</td><td>Not interchangeable with 0 and 1</td></tr></tbody></table></div></article><article class="concept-block"><h3>3. Conversions and promotion</h3><p>A widening primitive conversion generally preserves the represented magnitude and is allowed implicitly, such as int to long. Narrowing requires a cast because information may be lost, such as double to int or int to byte.</p><p>Arithmetic promotion can surprise beginners. Operations on byte, short and char values generally produce int. Integer division discards the fractional part before assignment, even if the destination is double.</p><ul><li><code>double average = total / count;</code> still uses integer division when both operands are int.</li><li>Use <code>total / (double) count</code> when fractional division is required.</li><li>A cast permits conversion; it does not guarantee the result is meaningful.</li></ul><div class="concept-note"><strong>Important:</strong> Use <code>BigDecimal</code> for exact base-10 financial rules and construct it from a String when decimal spelling matters.</div></article><article class="concept-block"><h3>4. Reading input with Scanner</h3><p>Scanner token methods such as <code>nextInt()</code> skip delimiters and leave the line-ending character unread. <code>nextLine()</code> consumes the remainder of the current line. Calling it immediately after a numeric token can therefore return an empty string.</p><p>A reliable pattern is to read a complete line and parse it, or explicitly consume the pending newline before reading free-form text. Validate input and give the user a corrective message rather than allowing an exception to terminate the program.</p><ul><li>Use <code>hasNextInt()</code> before <code>nextInt()</code> for interactive validation.</li><li>Use try-with-resources carefully: closing a Scanner over <code>System.in</code> closes standard input.</li><li>For programming contests, buffered input is faster for large data.</li></ul></article><article class="concept-block"><h3>5. Worked reasoning: cast before division, then test the boundaries</h3><p>A cast outside parentheses cannot recover a fraction already discarded by integer division. With total = 17 and count = 4, (double) (total / count) becomes (double) 4, or 4.0. Casting an operand first makes the division floating point and produces 4.25.</p><p>For -17 / 4, Java integer division truncates toward zero, producing -4 rather than -5. Zero as a numerator is valid; a count of zero is invalid for an average. This example rejects zero and negative counts before either division. Without that guard, the integer division would throw ArithmeticException; floating-point division by zero has different rules and does not validate the input for you.</p><p>Each call performs a fixed number of primitive operations: Θ(1) time and Θ(1) auxiliary space. An average computed by first summing n values would additionally need Θ(n) time for that sum. The supplied int total must already fit within the int range; converting after an overflowing sum cannot repair it.</p><ul><li>17, 4: distinguish 4.0 from 4.25.</li><li>-17, 4: distinguish truncation toward zero from rounding down.</li><li>0, 4: a valid zero average.</li><li>17, 0: reject the count before division.</li></ul></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Read a complete student record</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>import java.util.Scanner;

public class Program {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        System.out.print(&quot;Roll number: &quot;);
        int roll = input.nextInt();
        input.nextLine(); // consume the pending line break
        System.out.print(&quot;Full name: &quot;);
        String name = input.nextLine();
        System.out.print(&quot;CGPA: &quot;);
        double cgpa = input.nextDouble();
        System.out.printf(&quot;%d | %s | %.2f%n&quot;, roll, name, cgpa);
    }
}</code></pre></div><footer>The extra <code>nextLine()</code> after <code>nextInt()</code> consumes the remaining newline, allowing the following full-name read to work correctly.<pre>Output:
101 | Ananya Rao | 8.45</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Avoid accidental integer division</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    public static void main(String[] args) {
        int total = 17;

        System.out.println(wrong);
        System.out.println(correct);
    }
}</code></pre></div><footer>The first division is completed as int before assignment. Casting one operand promotes the second calculation to double.<pre>Output:

4.25</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 03</span><h3>Boundary test: the position of a cast matters</h3></div><button class="copy-code" type="button" data-copy-example="2">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    static void showAverage(int total, int count) {
        if (count &lt;= 0) {
            System.out.println(&quot;Count must be positive&quot;);
            return;
        }
        double tooLate = (double) (total / count);
        double correct = (double) total / count;
        System.out.println(&quot;Cast after division: &quot; + tooLate);
        System.out.println(&quot;Cast before division: &quot; + correct);
    }

    public static void main(String[] args) {
        showAverage(17, 4);
        showAverage(-17, 4);
        showAverage(0, 4);
        showAverage(17, 0);
    }
}</code></pre></div><footer>Read each pair as the result of casting after integer division, followed by casting before division. The guard returns early for an invalid count. Save as Program.java; each listed example is a separate program.<pre>Output:

reference variables identify objects or null.</div><div><b>03</b> Widening is usually implicit, while narrowing requires a cast.</div><div><b>04</b> Expression evaluation happens before assignment conversion.</div><div><b>05</b> Integer division discards the fractional portion.</div><div><b>06</b> Scanner token reads and line reads treat newlines differently.</div></div></section><section class="lesson-section" id="interview"><header class="section-heading"><span>INTERVIEW QUESTIONS</span><h2>Explain, Do Not Memorize</h2><p>Open each answer only after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. How are primitives different from references?</summary><p>A primitive variable contains a value of one of eight built-in types. A reference variable contains a reference to an object or null; assigning it copies the reference, not the object.</p></details><details><summary>2. Why does double x = 5 / 2 produce 2.0?</summary><p>Both operands are int, so integer division produces 2. That int result is then widened to double. Make at least one operand floating point to obtain 2.5.</p></details><details><summary>3. Is char equivalent to a Unicode character?</summary><p>A char is one UTF-16 code unit. Some Unicode characters require a surrogate pair and therefore two char values. Code-point APIs are needed for full Unicode processing.</p></details><details><summary>4. What is type inference with var?</summary><p>The compiler infers the static type of an initialized local variable from its initializer. It is not dynamic typing and the variable cannot later hold an unrelated type.</p></details><details><summary>5. Why can Scanner nextLine return empty after nextInt?</summary><p>nextInt consumes the numeric token but not the terminating newline. The following nextLine reads that remaining empty portion of the line.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
