CORE LIBRARIES · LEVEL 15</p><h1>Generics &amp; Type Safety</h1><p class="lead">Express reusable algorithms with compile-time type relationships while understanding invariance, bounds and erasure.</p><div class="lesson-meta"><span>Level 15 of 24</span><span>Intermediate</span><span>110–150 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Use generic APIs without unsafe casts</h2><ul><li>Define generic classes and methods.</li><li>Explain invariance.</li><li>Apply bounded wildcards.</li><li>Use PECS.</li><li>Understand erasure limits.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Generics &amp; Type Safety: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. Parameterized types</h3><p>Generics let one declaration preserve a relationship between input and output types. The compiler rejects incompatible operations and inserts necessary casts safely.</p><p>Use type parameters for relationships, not to replace every concrete domain type.</p></article><article class="concept-block"><h3>2. Invariance and wildcards</h3><p><code>List&lt;Integer&gt;</code> is not a subtype of <code>List&lt;Number&gt;</code> because writing a Double through the latter would corrupt the former.</p><p><code>? extends T</code> describes an unknown subtype source that is safe to read as T; <code>? super T</code> describes a destination that safely accepts T.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Form</th><th>Safe operation</th><th>Mnemonic</th></tr></thead><tbody><tr><td>List&lt;T&gt;</td><td>Read and write T</td><td>Exact type</td></tr><tr><td>List&lt;? extends T&gt;</td><td>Read T</td><td>Producer extends</td></tr><tr><td>List&lt;? super T&gt;</td><td>Write T</td><td>Consumer super</td></tr><tr><td>List&lt;?&gt;</td><td>Read Object</td><td>Unknown</td></tr></tbody></table></div></article><article class="concept-block"><h3>3. Bounds and erasure</h3><p>Bounds such as <code>&lt;T extends Comparable&lt;? super T&gt;&gt;</code> state capabilities needed by an algorithm.</p><p>Type arguments are mostly erased at runtime, so code cannot create <code>new T()</code>, use primitive type arguments or reliably test <code>instanceof List&lt;String&gt;</code>.</p><div class="concept-note"><strong>Important:</strong> Avoid raw types; they disable generic guarantees and can postpone failure to a distant cast.</div></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Generic maximum</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    static &lt;T extends Comparable&lt;? super T&gt;&gt; T max(T a,T b){return a.compareTo(b)&gt;=0?a:b;}
    public static void main(String[] args){System.out.println(max(&quot;Java&quot;,&quot;Kotlin&quot;));}
}</code></pre></div><footer>The bound states exactly the comparison capability the method needs.<pre>Output:
Kotlin</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Copy with PECS</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>import java.util.*;
public class Program {
    static &lt;T&gt; void copy(List&lt;? extends T&gt; src,List&lt;? super T&gt; dst){for(T item:src)dst.add(item);}
    public static void main(String[] args){List&lt;Integer&gt; s=List.of(2,4);List&lt;Number&gt;d=new ArrayList&lt;&gt;();copy(s,d);System.out.println(d);}
}</code></pre></div><footer>The source produces T-compatible values; the destination consumes T values.<pre>Output:
[2, 4]</pre></footer></article></section><section class="lesson-section" id="revision"><header class="section-heading"><span>QUICK REVISION</span><h2>Recall the Essential Ideas</h2></header><div class="revision-grid"><div><b>01</b> Generics preserve compile-time type relationships.</div><div><b>02</b> Generic types are invariant.</div><div><b>03</b> Producer extends, consumer super.</div><div><b>04</b> Bounds declare required capabilities.</div><div><b>05</b> Raw types remove guarantees.</div><div><b>06</b> Erasure limits runtime type inspection.</div></div></section><section class="lesson-section" id="interview"><header class="section-heading"><span>INTERVIEW QUESTIONS</span><h2>Explain, Do Not Memorize</h2><p>Open each answer only after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. Why is List&lt;Integer&gt; not List&lt;Number&gt;?</summary><p>If it were, a Double could be added through the Number view and later violate Integer expectations.</p></details><details><summary>2. Explain PECS.</summary><p>Use extends when a structure produces values for you and super when it consumes values from you.</p></details><details><summary>3. What is type erasure?</summary><p>Most generic type arguments are removed from runtime representation, with casts and bridge methods preserving source semantics.</p></details><details><summary>4. Can generics use int?</summary><p>No. Type arguments are reference types; use Integer, accepting boxing costs.</p></details><details><summary>5. What is a raw type?</summary><p>Using a generic declaration without arguments, such as List. It exists for compatibility and loses type safety.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler. Test normal input, a boundary value and one invalid case where relevant.</p></header><div class="practice-grid"><article class="practice-card"><span>PROBLEM 01</span><h3>Generic stack</h3><p>Implement push, pop and peek.</p><details><summary>Show guidance</summary><p>Decide empty-stack policy.</p></details></article><article class="practice-card"><span>PROBLEM 02</span><h3>Number sum</h3><p>Sum a producer of Number subtypes.</p><details><summary>Show guidance</summary><p>Accept <code>List&lt;? extends Number&gt;</code>.</p></details></article><article class="practice-card"><span>PROBLEM 03</span><h3>Comparator chooser</h3><p>Find best item using Comparator.</p><details><summary>Show guidance</summary><p>Use <code>Comparator&lt;? super T&gt;</code>.</p></details></article><article class="practice-card"><span>PROBLEM 04</span><h3>Wildcard lab</h3><p>Test allowed reads/writes for each wildcard.</p><details><summary>Show guidance</summary><p>Record compiler outcomes.</p></details></article></div></section><section class="lesson-section" id="quiz"><header class="section-heading"><span>CONCEPT CHECK</span><h2>Verify Your Understanding</h2><p>Every answer shows the correct choice and the reason immediately.</p></header><div class="quiz-list" id="quizList"><details class="quiz-card"><summary>Generic types mainly improve:</summary><ol><li>Compile-time safety</li><li>Network speed</li><li>GC timing</li><li>SQL syntax</li></ol><p><strong>Answer: Compile-time safety</strong> They catch type mismatches before runtime.</p></details><details class="quiz-card"><summary>List&lt;Integer&gt; subtype of List&lt;Number&gt;?</summary><ol><li>No</li><li>Yes</li><li>Only final</li><li>Only empty</li></ol><p><strong>Answer: No</strong> Generics are invariant.</p></details><details class="quiz-card"><summary>Producer wildcard:</summary><ol><li>? extends T</li><li>? super T</li><li>? equals T</li><li>raw</li></ol><p><strong>Answer: ? extends T</strong> It can be read as T.</p></details><details class="quiz-card"><summary>Consumer wildcard:</summary><ol><li>? super T</li><li>? extends T</li><li>? void</li><li>? static</li></ol><p><strong>Answer: ? super T</strong> It safely accepts T.</p></details><details class="quiz-card"><summary>Can use List&lt;int&gt;?</summary><ol><li>No</li><li>Yes</li><li>Only arrays</li><li>Only records</li></ol><p><strong>Answer: No</strong> Type arguments must be reference types.</p></details><details class="quiz-card"><summary>Raw types:</summary><ol><li>Lose type guarantees</li><li>Add stronger checks</li><li>Are primitives</li><li>Preserve every argument</li></ol><p><strong>Answer: Lose type guarantees</strong> Unchecked operations become possible.</p></details><details class="quiz-card"><summary>new T() is generally allowed?</summary><ol><li>No</li><li>Yes</li><li>Only in static</li><li>Only with List</li></ol><p><strong>Answer: No</strong> Erasure and unknown constructors prevent it.</p></details><details class="quiz-card"><summary>A bound states:</summary><ol><li>Required capabilities</li><li>Array length</li><li>Thread count</li><li>File path</li></ol><p><strong>Answer: Required capabilities</strong> The algorithm can call members guaranteed by the bound.</p></details></div><div class="quiz-score" id="quizScore">Correct: 0 of 0 attempted · 8 total</div></section><section class="lesson-section lesson-summary" id="summary"><div><p class="section-label">LEVEL 15 SUMMARY</p><h2>You can apply Generics &amp;
