CORE LIBRARIES · LEVEL 16</p><h1>Collections Framework</h1><p class="lead">Choose List, Set, Queue or Map from the operations and guarantees the problem actually requires.</p><div class="lesson-meta"><span>Level 16 of 24</span><span>Intermediate</span><span>110–150 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Select and use collection implementations deliberately</h2><ul><li>Choose by semantics and complexity.</li><li>Use iteration safely.</li><li>Implement equals/hashCode keys.</li><li>Order with Comparable/Comparator.</li><li>Recognize immutable views.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#trace">Trace</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Collections Framework: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. Interface-first selection</h3><p>List preserves sequence and duplicates; Set enforces uniqueness; Queue models pending order; Map associates unique keys with values.</p><p>Choose an implementation from access, update, ordering and concurrency requirements rather than habit.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Type</th><th>Strength</th><th>Typical cost</th></tr></thead><tbody><tr><td>ArrayList</td><td>Indexed access, append</td><td>O(1) average append</td></tr><tr><td>HashSet</td><td>Membership</td><td>O(1) average</td></tr><tr><td>TreeSet</td><td>Sorted unique values</td><td>O(log n)</td></tr><tr><td>HashMap</td><td>Key lookup</td><td>O(1) average</td></tr><tr><td>ArrayDeque</td><td>Ends of queue/stack</td><td>O(1) average</td></tr></tbody></table></div></article><article class="concept-block"><h3>2. Equality, hashing and order</h3><p>Hash collections use hashCode to choose a region and equals to confirm a match. Equal objects must have equal hash codes, and key fields must remain stable while stored.</p><p>Comparable defines natural order; Comparator defines external order. A sorted set/map treats comparator equality as key equality.</p></article><article class="concept-block"><h3>3. Mutation and views</h3><p>Structural mutation during enhanced iteration usually triggers fail-fast behaviour. Use Iterator.remove, removeIf or collect changes separately.</p><p>Factory collections such as List.of are unmodifiable. <code>Collections.unmodifiableList</code> is a view that may reflect backing-list changes; <code>List.copyOf</code> creates an unmodifiable snapshot of references.</p><div class="concept-note"><strong>Important:</strong> Never rely on HashMap iteration order unless a specific ordered implementation is chosen.</div></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Frequency map</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>import java.util.*;
public class Program {
    public static void main(String[] args){
        String[] words={&quot;java&quot;,&quot;map&quot;,&quot;java&quot;,&quot;safe&quot;};
        Map&lt;String,Integer&gt; counts=new LinkedHashMap&lt;&gt;();
        for(String word:words)counts.merge(word,1,Integer::sum);
        System.out.println(counts);
    }
}</code></pre></div><footer>merge expresses initialize-or-increment, while LinkedHashMap preserves encounter order deliberately.<pre>Output:
{java=2, map=1, safe=1}</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Comparator chain</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>import java.util.*;
public class Program {
    record Student(String name,int mark){}
    public static void main(String[] args){
        List&lt;Student&gt; s=new ArrayList&lt;&gt;(List.of(new Student(&quot;B&quot;,80),new Student(&quot;A&quot;,80),new Student(&quot;C&quot;,92)));
        s.sort(Comparator.comparingInt(Student::mark).reversed().thenComparing(Student::name));
        System.out.println(s);
    }
}</code></pre></div><footer>The comparator makes both primary and tie-break order explicit.<pre>Output:
[Student[name=C, mark=92], Student[name=A, mark=80], Student[name=B, mark=80]]</pre></footer></article></section><section class="lesson-section" id="trace"><header answer only after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. ArrayList versus LinkedList?</summary><p>ArrayList usually offers better locality and indexed access; LinkedList helps only in specific node-position insertion patterns and has traversal overhead.</p></details><details><summary>2. HashMap versus TreeMap?</summary><p>HashMap offers average constant lookup without sorted order; TreeMap offers key order and logarithmic operations.</p></details><details><summary>3. equals/hashCode contract?</summary><p>Equal objects must produce equal hash codes; unequal objects may collide. Both should remain consistent while used as keys.</p></details><details><summary>4. Why ConcurrentModificationException?</summary><p>Fail-fast iterators detect unsupported structural changes, helping expose unsafe traversal logic; it is not a concurrency guarantee.</p></details><details><summary>5. Comparable versus Comparator?</summary><p>Comparable is a type&#39;s natural order; Comparator is a separate replaceable ordering policy.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
