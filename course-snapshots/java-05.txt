Pattern Reasoning</h1><p class="lead">Control repetition using invariants, termination arguments and carefully placed updates rather than trial and error.</p><div class="lesson-meta"><span>Level 5 of 24</span><span>Beginner</span><span>110–150 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Write terminating loops and trace their state</h2><ul><li>Choose for, while or do-while.</li><li>State a loop invariant.</li><li>Prevent off-by-one errors.</li><li>Use break and continue intentionally.</li><li>Estimate nested-loop work.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#trace">Trace</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Loops &amp; Pattern Reasoning: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. The loop contract</h3><p>A loop needs initialization, a continuation test, useful work and progress toward termination. An invariant describes what remains true before every iteration.</p><p>For counters, decide whether the range is inclusive or exclusive before coding. <code>0 &lt;= i &amp;&amp; i &lt; length</code> matches Java indexing.</p><ul><li>Initialization establishes the invariant.</li><li>The body preserves it while advancing state.</li><li>Termination plus the invariant implies the result.</li></ul></article><article class="concept-block"><h3>2. Choose the form</h3><p>Use <code>for</code> when counter policy fits its header, <code>while</code> when input or changing state controls repetition, and <code>do-while</code> when work must happen once before testing.</p><p>The form communicates intent even when one form could be rewritten as another.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Loop</th><th>Test</th><th>Typical use</th></tr></thead><tbody><tr><td>for</td><td>Before</td><td>Counted traversal</td></tr><tr><td>while</td><td>Before</td><td>Sentinel/state</td></tr><tr><td>do-while</td><td>After</td><td>Menu/retry</td></tr></tbody></table></div></article><article class="concept-block"><h3>3. Control and nesting</h3><p><code>break</code> exits the nearest loop; <code>continue</code> skips the remaining body. Both should express a named policy, not patch unclear logic.</p><p>Nested loops do not automatically mean O(n²); count actual inner executions as a function of the outer index.</p><div class="concept-note"><strong>Important:</strong> A continue inside while can skip a manual update and cause non-termination.</div></article><article class="concept-block"><h3>4. Patterns</h3><p>For output patterns, let the outer loop choose a row and derive the counts of spaces and symbols from that row.</p><p>Trace small inputs in a table of starting state, body work and ending state to expose off-by-one errors.</p></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Analyse decimal digits</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    public static void main(String[] args) {
        int value = 53042, sum = 0, digits = 0;
        do {
            sum += value % 10;
            digits++;
            value /= 10;
        } while (value != 0);
        System.out.println(digits + &quot; digits, sum=&quot; + sum);
    }
}</code></pre></div><footer>do-while treats zero as one digit. Each iteration removes exactly one decimal digit.<pre>Output:
5 digits, sum=14</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Test primality</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    static boolean isPrime(int n) {
        if (n &lt; 2) return false;
        for (int d = 2; d &lt;= n / d; d++) {
            if (n % d == 0) return false;
        }
        return true;
    }
    public static void main(String[] args) {
        System.out.println(isPrime(29));
    }
}</code></pre></div><footer>A composite number has a factor at or below its square root. Division in the condition avoids multiplication overflow.<pre>Output:
true</pre></footer></article></section><section class="lesson-section" id="trace"><header class="section-heading"><span>INTERACTIVE LEARNING · PROGRAM TRACE</span><h2>Trace a digit loop</h2><p>Watch the variant shrink to termination.</p></header><div class="visualizer"><div class="trace-code"><header>JAVA EXECUTION</header><div class="trace-lines" id="traceLines"><div class="trace-line" data-line="1"><b>1</b><span>int value=530, sum=0;</span></div><div class="trace-line" data-line="2"><b>2</b><span>while (value != 0) {</span></div><div class="trace-line" data-line="3"><b>3</b><span> int digit=value%10;</span></div><div class="trace-line" data-line="4"><b>4</b><span> sum+=digit;</span></div><div class="trace-line" data-line="5"><b>5</b><span> value/=10;</span></div><div class="trace-line" data-line="6"><b>6</b><span>}</span></div><div class="trace-line" data-line="7"><b>7</b><span>print sum;</span></div></div></div><div class="trace-state"><header>VISIBLE RUNTIME STATE</header><div class="trace-stage"><span id="traceCounter">READY</span><h3 id="traceTitle">Start the trace</h3><p id="traceText">Move line by line and connect the Java statement to its runtime effect.</p><div class="state-box" id="traceState">No state change yet.</div></div><div class="trace-controls"><button id="traceNext">Next step →</button><button id="traceAuto">▶ Auto run</button><button id="traceReset">Reset</button></div></div></div></section><section class="lesson-section" id="revision"><header class="section-heading"><span>QUICK REVISION</span><h2>Recall the Essential Ideas</h2></header><div class="revision-grid"><div><b>01</b> Every loop needs progress toward termination.</div><div><b>02</b> for suits counted traversal.</div><div><b>03</b> while suits state-driven repetition.</div><div><b>04</b> do-while runs once before testing.</div><div><b>05</b> break exits; continue skips ahead.</div><div><b>06</b> Nested-loop cost comes from execution counts.</div></div></section><section class="lesson-section" id="interview"><header class="section-heading"><span>INTERVIEW QUESTIONS</span><h2>Explain, Do Not Memorize</h2><p>Open each answer only after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. What is a loop invariant?</summary><p>A property true before each iteration that describes the partial result and helps prove correctness.</p></details><details><summary>2. What causes off-by-one errors?</summary><p>A mismatch between intended range boundaries and initialization, comparison or update.</p></details><details><summary>3. When use do-while?</summary><p>When the first action must happen before continuation can be decided.</p></details><details><summary>4. Is break bad practice?</summary><p>No. A focused early exit is clear; many unexplained exits make reasoning harder.</p></details><details><summary>5. How do you estimate nested-loop time?</summary><p>Count the inner-body executions for each outer state and sum them.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
