completion occurs later rather than immediately in the current execution flow.</p></div></article><article><b>02</b><div><strong>Promise</strong><p>An object representing the eventual success or failure of an asynchronous operation.</p></div></article><article><b>03</b><div><strong>Pending</strong><p>Initial Promise state before it fulfills or rejects.</p></div></article><article><b>04</b><div><strong>Fulfilled</strong><p>Promise state representing successful completion.</p></div></article><article><b>05</b><div><strong>Rejected</strong><p>Promise state representing failure.</p></div></article><article><b>06</b><div><strong>then()</strong><p>Registers handling for fulfilled Promise results.</p></div></article><article><b>07</b><div><strong>catch()</strong><p>Handles Promise rejection and errors propagated through a chain.</p></div></article><article><b>08</b><div><strong>finally()</strong><p>Runs after a Promise settles regardless of success or failure.</p></div></article><article><b>09</b><div><strong>async</strong><p>Declares a function that returns a Promise.</p></div></article><article><b>10</b><div><strong>await</strong><p>Suspends the requests.</p></div></article><article><b>12</b><div><strong>Response</strong><p>Object representing the HTTP response received by Fetch.</p></div></article><article><b>13</b><div><strong>response.ok</strong><p>Boolean indicating whether the HTTP status is in the successful 200 range.</p></div></article><article><b>14</b><div><strong>JSON</strong><p>Text-based data format commonly used for API communication.</p></div></article><article><b>15</b><div><strong>Promise.all()</strong><p>Waits for multiple Promises and rejects when one rejects.</p></div></article><article><b>16</b><div><strong>Promise.allSettled()</strong><p>Waits for every Promise and reports each outcome.</p></div></article><article><b>17</b><div><strong>Promise.race()</strong><p>Settles according to the first Promise to settle.</p></div></article><article><b>18</b><div><strong>Promise.any()</strong><p>Fulfills when the first Promise fulfills.</p></div></article><article><b>19</b><div><strong>Event loop</strong><p>The runtime mechanism that coordinates execution of queued asynchronous work.</p></div></article><article><b>20</b><div><strong>Microtask</strong><p>A high-priority queued job such as a Promise reaction.</p></div></article><article><b>21</b><div><strong>AbortController</strong><p>API used to signal cancellation to compatible asynchronous operations.</p></div></article></div></section><section class="lesson-section interview-section"><p class="section-label">PLACEMENT & INTERVIEW</p><h2>Explain the concept, don't just memorize it</h2><div class="interview-list"><details class="interview-item"><summary><span>01</span>What is asynchronous JavaScript?</summary><div class="interview-answer"><p>It is a programming model where operations can complete later without forcing the current JavaScript execution to wait for them synchronously.</p></div></details><details class="interview-item"><summary><span>02</span>Why do we need asynchronous programming in browsers?</summary><div class="interview-answer"><p>Browsers perform operations such as network requests and timers whose completion time is unknown. Asynchronous programming allows the application to remain responsive while those operations are pending.</p></div></details><details class="interview-item"><summary><span>03</span>What is a Promise?</summary><div class="interview-answer"><p>A Promise represents the eventual result of an asynchronous operation and can be pending, fulfilled or rejected.</p></div></details><details class="interview-item"><summary><span>04</span>What are the three Promise states?</summary><div class="interview-answer"><p>Pending, fulfilled and rejected.</p></div></details><details class="interview-item"><summary><span>05</span>What does then() do?</summary><div class="interview-answer"><p>It registers a handler that runs when the Promise is fulfilled and returns another Promise for chaining.</p></div></details><details class="interview-item"><summary><span>06</span>What does catch() do?</summary><div class="interview-answer"><p>It handles Promise rejection and errors propagated through the Promise chain.</p></div></details><details class="interview-item"><summary><span>07</span>What does finally() do?</summary><div class="interview-answer"><p>It runs after a Promise settles regardless of whether it fulfilled or rejected.</p></div></details><details class="interview-item"><summary><span>08</span>What is Promise chaining?</summary><div class="interview-answer"><p>It is connecting asynchronous operations by returning Promises from then() handlers and handling their results in subsequent handlers.</p></div></details><details class="interview-item"><summary><span>09</span>What is a floating Promise?</summary><div class="interview-answer"><p>It is an asynchronous Promise that is started but not properly returned, awaited or otherwise handled by the surrounding logic.</p></div></details><details class="interview-item"><summary><span>10</span>What does async do to a function?</summary><div class="interview-answer"><p>It makes the function return a Promise and allows await to be used inside the function.</p></div></details><details class="interview-item"><summary><span>11</span>What does await do?</summary><div class="interview-answer"><p>It suspends the surrounding async function until the awaited Promise settles and then provides its fulfilled value or throws its rejection.</p></div></details><details class="interview-item"><summary><span>12</span>Does await block the entire JavaScript runtime?</summary><div class="interview-answer"><p>No. It suspends the surrounding async function while allowing other work to continue.</p></div></details><details class="interview-item"><summary><span>13</span>What does fetch() return?</summary><div class="interview-answer"><p>fetch() returns a Promise that fulfills with a Response object when a response is received.</p></div></details><details class="interview-item"><summary><span>14</span>Does fetch() reject when the server returns 404?</summary><div class="interview-answer"><p>Normally no. Fetch fulfills with a Response, so application code should check response.ok or response.status.</p></div></details><details class="interview-item"><summary><span>15</span>Why should response.ok be checked?</summary><div class="interview-answer"><p>Because an HTTP error status such as 404 or 500 does not by itself cause fetch() to reject.</p></div></details><details class="interview-item"><summary><span>16</span>How do you parse JSON from a Fetch response?</summary><div class="interview-answer"><p>Call await response.json() inside an async function or return response.json() in a Promise chain.</p></div></details><details class="interview-item"><summary><span>17</span>What is Promise.all() used for?</summary><div class="interview-answer"><p>It waits for multiple independent Promises and fulfills when all fulfill, while rejecting if one rejects.</p></div></details><details class="interview-item"><summary><span>18</span>When should Promise.all() be avoided?</summary><div class="interview-answer"><p>It should not be used when operations depend on each other or when one failure should not discard all other results.</p></div></details><details class="interview-item"><summary><span>19</span>What is the difference between Promise.all() and Promise.allSettled()?</summary><div class="interview-answer"><p>Promise.all() rejects when one Promise rejects, while Promise.allSettled() waits for every Promise and reports each result.</p></div></details><details class="interview-item"><summary><span>20</span>What is the event loop?</summary><div class="interview-answer"><p>It is the runtime mechanism that coordinates execution of synchronous JavaScript and queued asynchronous callbacks.</p></div></details><details class="interview-item"><summary><span>21</span>What is a microtask?</summary><div class="interview-answer"><p>A microtask is a queued job such as a Promise reaction that is processed after the current JavaScript stack completes and before the next eligible task.</p></div></details><details class="interview-item"><summary><span>22</span>Why can Promise callbacks run before setTimeout callbacks?</summary><div class="interview-answer"><p>Promise reactions are microtasks, while timer callbacks are tasks. Microtasks are processed before the next task in the relevant event-loop cycle.</p></div></details><details class="interview-item"><summary><span>23</span>What is AbortController used for?</summary><div class="interview-answer"><p>It provides a signal that can be used to cancel compatible operations such as Fetch requests.</p></div></details><details class="interview-item"><summary><span>24</span>What is the difference between a network error and an HTTP error?</summary><div class="interview-answer"><p>A network error can cause fetch() to reject, while an HTTP error such as 404 normally produces a Response whose ok property is false.</p></div></details><details class="interview-item"><summary><span>25</span>Why should loading, success and error states be designed separately?</summary><div class="interview-answer"><p>Because asynchronous operations have different phases and users need clear feedback about whether work is running, completed, empty or failed.</p></div></details></div></section><section class="lesson-section practice-section"><p class="section-label">PRACTICE ARENA</p><h2>Now apply what you learned</h2><p class="section-description">Try these problems without immediately looking at the solution.
