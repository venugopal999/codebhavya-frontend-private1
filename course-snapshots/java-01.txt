First Program</h1><p class="lead">Begin with the execution model: Java source is compiled into verified bytecode and executed by a Java Virtual Machine. This separation explains portability, runtime checks, class loading and later JVM behaviour.</p><div class="lesson-meta"><span>Level 1 of 24</span><span>Beginner</span><span>90–120 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Trace source code from javac to JVM output</h2><ul><li>Distinguish JDK, runtime environment and JVM responsibilities.</li><li>Explain source, bytecode and machine-code stages.</li><li>Read the structure of a minimal Java class.</li><li>Compile and run a program from the command line.</li><li>Interpret common filename, class and main-method errors.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#trace">Trace</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Understand the Platform before Memorizing Syntax</h2><p>Java is both a language and an execution platform. Keeping compiler-time and runtime responsibilities separate prevents many beginner misconceptions.</p></header><article class="concept-block"><h3>1. JDK, runtime and JVM</h3><p>The Java Development Kit contains developer tools such as <code>javac</code>, <code>java</code>, <code>javadoc</code> and diagnostics. The runtime libraries and JVM are what a machine needs to execute compiled Java applications. In modern Java distributions, developers normally install a JDK and use its included runtime.</p><p>The JVM is an abstract machine specification with platform-specific implementations. It loads classes, verifies bytecode, manages memory, interprets or compiles hot code and provides services such as exceptions and threads.</p><ul><li>JDK: build, inspect and run Java software.</li><li>Runtime libraries: standard classes used by applications.</li><li>JVM: executes bytecode and manages runtime state.</li></ul><div class="concept-note"><strong>Important:</strong> Do not say Java is completely platform independent. Bytecode is portable, while each operating system needs a compatible JVM implementation.</div></article><article class="concept-block"><h3>2. Source to execution</h3><p>A <code>.java</code> file is compiled by <code>javac</code>. The compiler performs lexical, syntax and type checks, then writes one or more <code>.class</code> files containing bytecode. The <code>java</code> launcher starts a JVM and asks it to run a class containing a valid entry point.</p><p>The class loader locates required classes. The verifier checks bytecode safety properties. The execution engine initially interprets instructions and may use a just-in-time compiler for frequently executed methods.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Stage</th><th>Input</th><th>Output or responsibility</th></tr></thead><tbody><tr><td>Compile</td><td>Program.java</td><td>Program.class bytecode</td></tr><tr><td>Load</td><td>Requested class</td><td>Runtime Class object and metadata</td></tr><tr><td>Verify</td><td>Bytecode</td><td>Structural and type-safety checks</td></tr><tr><td>Execute</td><td>Verified methods</td><td>Interpreted/JIT-compiled machine work</td></tr></tbody></table></div></article><article class="concept-block"><h3>3. Anatomy of the first program</h3><p>A class groups state and behaviour. <code>public class Program</code> declares a type visible to other code. When the class is public, its source filename must match the class name exactly, including capitalization.</p><p>The launcher recognizes <code>public static void main(String[] args)</code> as the conventional entry point. <code>public</code> permits launcher access, <code>static</code> avoids constructing an object first, <code>void</code> means no value is returned, and <code>args</code> holds command-line strings.</p><ul><li>Java is case-sensitive: <code>String</code> and <code>string</code> differ.</li><li>Statements normally end with a semicolon.</li><li>Blocks are delimited by braces.</li><li><code>System.out.println</code> writes a value followed by a line break.</li></ul><div class="concept-note"><strong>Important:</strong> A successful compilation proves syntax and type consistency, not that the program produces the intended answer.</div></article><article class="concept-block"><h3>4. Compile-time versus runtime failures</h3><p>A compiler error prevents bytecode creation: missing semicolon, incompatible type or unresolved name. A runtime exception occurs after execution starts: division by zero, invalid index or missing file. A logic error completes normally but produces the wrong result.</p><p>Classify the failure before editing. Read the first diagnostic, identify the file and line, then fix the cause rather than changing unrelated statements.</p><ul><li>Compile error: correct source structure or types.</li><li>Runtime error: inspect input and execution state.</li><li>Logic error: compare actual behaviour with the requirement.</li></ul></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>First executable class</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {

    }
}</code></pre></div><footer>The local reference <code>learner</code> points to a String. Concatenation builds the greeting, while <code>args.length</code> reports how many command-line values were supplied.<pre>Output:

Arguments received: 0</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Predictable numeric output</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {

Total = 20</pre></footer></article></section><section class="lesson-section" id="trace"><header class="section-heading"><span>INTERACTIVE LEARNING · PROGRAM TRACE</span><h2>Trace Java&#39;s launch sequence</h2><p>Follow one source file through compilation, loading and execution.</p></header><div class="visualizer"><div class="trace-code"><header>JAVA EXECUTION</header><div class="trace-lines" id="traceLines"><div class="trace-line" data-line="1"><b>1</b><span>public class Program {</span></div><div class="trace-line" data-line="2"><b>2</b><span>  public static void main(String[] args) {</span></div><div class="trace-line" data-line="3"><b>3</b><span>    System.out.println(&quot;Hello, Java!&quot;);</span></div><div class="trace-line" data-line="4"><b>4</b><span>  }</span></div><div class="trace-line" data-line="5"><b>5</b><span>}</span></div></div></div><div class="trace-state"><header>VISIBLE RUNTIME STATE</header><div class="trace-stage"><span id="traceCounter">READY</span><h3 id="traceTitle">Start the trace</h3><p id="traceText">Move line by line and connect the Java statement to its runtime effect.</p><div class="state-box" id="traceState">No state change yet.</div></div><div class="trace-controls"><button id="traceNext">Next step →</button><button id="traceAuto">▶ Auto run</button><button id="traceReset">Reset</button></div></div></div></section><section class="lesson-section" id="revision"><header class="section-heading"><span>QUICK REVISION</span><h2>Recall the Essential Ideas</h2></header><div class="revision-grid"><div><b>01</b> <code>javac</code> compiles source into bytecode; <code>java</code> launches a JVM.</div><div><b>02</b> The JDK includes development tools and an execution runtime.</div><div><b>03</b> A public class name must match its source filename.</div><div><b>04</b> The standard entry point is <code>public static void main(String[] args)</code>.</div><div><b>05</b> Compile, runtime and logic errors require different debugging approaches.</div><div><b>06</b> Bytecode portability still depends on a compatible platform JVM.</div></div></section><section class="lesson-section" id="interview"><header class="section-heading"><span>INTERVIEW QUESTIONS</span><h2>Explain, Do Not Memorize</h2><p>Open each answer only after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. Why is Java called platform independent?</summary><p>The compiler targets JVM bytecode rather than one operating system&#39;s machine code. The same class files can run where a compatible JVM and required libraries exist. The JVM implementation itself is platform specific.</p></details><details><summary>2. What is the difference between JDK and JVM?</summary><p>The JDK is the developer distribution containing the compiler, launcher and tools. The JVM is the execution engine that loads, verifies and runs bytecode while managing runtime resources.</p></details><details><summary>3. Why is main static?</summary><p>The launcher needs a known entry point before an application object exists. A static method belongs to the class, so it can be invoked without first calling a constructor.</p></details><details><summary>4. Does bytecode run directly on the CPU?</summary><p>Normally no. The JVM interprets bytecode or compiles selected methods into native machine instructions using the JIT compiler.</p></details><details><summary>5. What does the bytecode verifier do?</summary><p>It checks structural rules such as valid instruction forms, stack usage and compatible types before execution, strengthening the JVM safety boundary.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
