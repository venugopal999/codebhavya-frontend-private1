CORE LIBRARIES · LEVEL 19</p><h1>File I/O, NIO &amp; Serialization</h1><p class="lead">Read and write data with explicit encoding, deterministic resource ownership and safe persistence formats.</p><div class="lesson-meta"><span>Level 19 of 24</span><span>Intermediate</span><span>110–150 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Build reliable file-processing boundaries</h2><ul><li>Choose byte or character I/O.</li><li>Use Path and Files.</li><li>Specify charsets.</li><li>Stream large files.</li><li>Avoid unsafe native serialization.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>File I/O, NIO &amp; Serialization: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. Bytes, characters and encoding</h3><p>Streams read bytes; Readers/Writers read characters through a charset. Text without a declared encoding is ambiguous.</p><p>Use StandardCharsets.UTF_8 for portable data unless a format specifies otherwise.</p></article><article class="concept-block"><h3>2. NIO file operations</h3><p>Path represents a filesystem path; Files supplies high-level read, write, copy, move, directory and metadata operations.</p><p>Small convenience methods load entire content; use buffered or line streaming APIs for large files and close returned streams.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Need</th><th>API</th><th>Memory</th></tr></thead><tbody><tr><td>Small text</td><td>Files.readString</td><td>Whole file</td></tr><tr><td>Large text</td><td>Files.lines/BufferedReader</td><td>Incremental</td></tr><tr><td>Binary copy</td><td>Files.copy</td><td>Streaming internally</td></tr><tr><td>Directory walk</td><td>Files.walk</td><td>Lazy stream; close it</td></tr></tbody></table></div></article><article class="concept-block"><h3>3. Persistence safety</h3><p>Write temporary output and atomically move it when replacing important data where the filesystem supports it. Validate paths, sizes and formats before trusting input.</p><p>Native Java object serialization couples data to implementation and has security risks for untrusted input. Prefer explicit JSON, CSV or schema-based formats with validation.</p><div class="concept-note"><strong>Important:</strong> Never deserialize untrusted native Java object streams.</div></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>UTF-8 round trip</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>import java.nio.file.*;import java.nio.charset.StandardCharsets;
public class Program {
    public static void main(String[] args) throws Exception{
        Path file=Files.createTempFile(&quot;codebhavya-&quot;,&quot;.txt&quot;);
        Files.writeString(file,&quot;Java ✓&quot;,StandardCharsets.UTF_8);
        System.out.println(Files.readString(file,StandardCharsets.UTF_8));
        Files.deleteIfExists(file);
    }
}</code></pre></div><footer>The program owns a temporary file, declares UTF-8 at both boundaries and removes the resource.<pre>Output:
Java ✓</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Incremental line count</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>import java.io.*;import java.util.*;

    public static void main(String[] args) throws Exception{

    }

2</pre></footer></article></section><section class="lesson-section" id="revision"><header class="section-heading"><span>QUICK REVISION</span><h2>Recall the Essential Ideas</h2></header><div class="revision-grid"><div><b>01</b> Bytes and characters are different abstractions.</div><div><b>02</b> Specify text encoding.</div><div><b>03</b> Path models location; Files performs operations.</div><div><b>04</b> Stream large inputs.</div><div><b>05</b> Close lazy file streams.</div><div><b>06</b> Avoid native deserialization of untrusted data.</div></div></section><section class="lesson-section" id="interview"><header class="section-heading"><span>INTERVIEW QUESTIONS</span><h2>Explain, Do Not Memorize</h2><p>Open each answer only after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. InputStream versus Reader?</summary><p>InputStream reads bytes; Reader decodes bytes into characters using a charset.</p></details><details><summary>2. Why buffered I/O?</summary><p>It reduces expensive underlying operations by moving data in larger blocks and provides convenient line APIs.</p></details><details><summary>3. Path versus File?</summary><p>Path is the modern NIO abstraction with richer Files operations and provider support; File is older.</p></details><details><summary>4. Why is object deserialization risky?</summary><p>Crafted object graphs can trigger dangerous construction/read hooks and couple input to implementation classes.</p></details><details><summary>5. How replace a critical file safely?</summary><p>Write and validate a temporary file, flush/close it, then move it over the target atomically when supported.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
