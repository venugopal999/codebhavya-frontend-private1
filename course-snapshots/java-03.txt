Expressions</h1><p class="lead">Learn how Java groups, promotes and evaluates operands. Correct expression reasoning prevents subtle bugs in totals, conditions, bit flags and short-circuit logic.</p><div class="lesson-meta"><span>Level 3 of 24</span><span>Beginner</span><span>100–130 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Evaluate expressions without trial and error</h2><ul><li>Use arithmetic, relational and logical operators correctly.</li><li>Apply precedence and associativity rules.</li><li>Explain short-circuit evaluation and side effects.</li><li>Use increment and compound assignment safely.</li><li>Perform basic bitwise and shift operations.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#trace">Trace</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>An Expression Has an Order, Type and Result</h2><p>Operators are not isolated symbols. Each expression combines precedence, associativity, promotion and possible side effects.</p></header><article class="concept-block"><h3>1. Arithmetic and remainder</h3><p>The arithmetic operators are addition, subtraction, multiplication, division and remainder. Division behaviour depends on operand types. Integer overflow does not automatically throw an exception; the result wraps according to two&#39;s-complement arithmetic.</p><p>Remainder is useful for parity, cyclic positions and digit extraction. In Java, its sign follows the dividend, so negative values need care when creating a non-negative modular index.</p><ul><li>Use <code>Math.floorMod(value, size)</code> for a non-negative cyclic index.</li><li>Do not compare floating-point calculations for exact equality unless the values are known exact.</li><li>Use checked methods such as <code>Math.addExact</code> when overflow must be detected.</li></ul></article><article class="concept-block"><h3>2. Precedence, associativity and parentheses</h3><p>Precedence decides which operator groups first; associativity resolves operators at the same precedence. Multiplication groups before addition, while assignment groups right to left. Parentheses are better than relying on readers to recall a long precedence table.</p><p>Evaluation order is still left to right for operands in Java. That matters when method calls or increments have side effects, even when operator grouping differs.</p><div class="concept-note"><strong>Important:</strong> Readable code avoids mixing several increments, assignments and arithmetic operations in one expression.</div></article><article class="concept-block"><h3>3. Relational, logical and short-circuit operators</h3><p>Relational operators create boolean results. <code>&amp;&amp;</code> and <code>||</code> short-circuit: the right operand is evaluated only when required to determine the result. <code>&amp;</code> and <code>|</code> can operate on booleans too, but they evaluate both sides.</p><p>Short-circuiting supports safe guards such as <code>text != null &amp;&amp; !text.isEmpty()</code>. Reversing these checks dereferences null before the guard can help.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Operator</th><th>Right side evaluated when</th><th>Typical use</th></tr></thead><tbody><tr><td>&amp;&amp;</td><td>Left side is true</td><td>All required conditions</td></tr><tr><td>||</td><td>Left side is false</td><td>At least one acceptable condition</td></tr><tr><td>!</td><td>Unary operand only</td><td>Negate a boolean</td></tr><tr><td>&amp; or | on boolean</td><td>Always</td><td>Rare cases requiring both evaluations</td></tr></tbody></table></div></article><article class="concept-block"><h3>4. Assignment, increment and bitwise work</h3><p>Compound assignment evaluates the left side once and includes an implicit cast to the left type. Therefore <code>byte b = 1; b += 200;</code> compiles but may narrow unexpectedly, whereas <code>b = b + 200</code> does not compile without a cast.</p><p>Bitwise operators manipulate integral bit patterns. AND tests flags, OR sets flags, XOR toggles differing bits, and shifts move bit positions. Use named masks and document the representation.</p><ul><li>Prefix increment changes then yields; postfix yields then changes.</li><li>Unsigned right shift <code>&gt;&gt;&gt;</code> inserts zero bits.</li><li>Shift distance is masked by the operand width.</li></ul><div class="concept-note"><strong>Important:</strong> Prefer simple separate statements when mutation order affects the answer.</div></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Short-circuit validation</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    static boolean validUsername(String name) {
        return name != null &amp;&amp; name.length() &gt;= 4 &amp;&amp; name.length() &lt;= 20;
    }

    public static void main(String[] args) {
        System.out.println(validUsername(null));
        System.out.println(validUsername(&quot;Bhavya&quot;));
    }
}</code></pre></div><footer>When name is null, the first condition is false and later calls are skipped, preventing a NullPointerException.<pre>Output:
false
true</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Decode permission flags</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    public static void main(String[] args) {
        int READ = 1;   // 001
        int WRITE = 2;  // 010
        int EXECUTE = 4;// 100
        int permissions = READ | WRITE;
        boolean canWrite = (permissions &amp; WRITE) != 0;
        System.out.println(canWrite);
        System.out.println(Integer.toBinaryString(permissions));
    }
}</code></pre></div><footer>OR combines flags; AND isolates the WRITE bit. Named masks make the bit representation auditable.<pre>Output:
true
11</pre></footer></article></section><section class="lesson-section" id="trace"><header class="section-heading"><span>INTERACTIVE LEARNING · PROGRAM TRACE</span><h2>Trace precedence and short-circuit evaluation</h2><p>Follow grouping and observe which operand is skipped.</p></header><div class="visualizer"><div class="trace-code"><header>JAVA EXECUTION</header><div class="trace-lines" id="traceLines"><div class="trace-line" data-line="1"><b>1</b><span>int x = 4;</span></div><div class="trace-line" data-line="2"><b>2</b><span>int y = 3;</span></div><div class="trace-line" data-line="3"><b>3</b><span>int result = x + y * 2;</span></div><div class="trace-line" data-line="4"><b>4</b><span>boolean safe = x &gt; What is the difference between &amp; and &amp;&amp;?</summary><p>For booleans, both compute AND, but &amp;&amp; short-circuits when the left side is false. &amp; evaluates both operands. On integral values, &amp; performs bitwise AND.</p></details><details><summary>2. What is the difference between i++ and ++i?</summary><p>Both increment i. Prefix yields the updated value; postfix yields the previous value and then increments. As standalone statements their final effect is the same.</p></details><details><summary>3. Why is String concatenation sometimes surprising?</summary><p>Once a String participates, + concatenates subsequent operands left to right. <code>&quot;Total: &quot; + 2 + 3</code> gives Total: 23; parentheses around 2 + 3 produce Total: 5.</p></details><details><summary>4. Does Java detect integer overflow?</summary><p>Normal primitive integer operations wrap without an exception. Use range checks, wider types or methods such as Math.addExact when overflow must fail.</p></details><details><summary>5. What is short-circuit evaluation useful for?</summary><p>It avoids unnecessary work and enables guards, for example checking a reference for null before calling a method on it.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
