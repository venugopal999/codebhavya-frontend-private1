CORE LIBRARIES · LEVEL 18</p><h1>Stream API &amp; Optional</h1><p class="lead">Build lazy data pipelines with explicit ordering, reduction and absence semantics.</p><div class="lesson-meta"><span>Level 18 of 24</span><span>Intermediate</span><span>110–150 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Transform data with correct stream and Optional contracts</h2><ul><li>Separate source, intermediates and terminal operations.</li><li>Use map/filter/flatMap.</li><li>Reduce safely.</li><li>Understand laziness and reuse.</li><li>Use Optional at return boundaries.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#trace">Trace</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Stream API &amp; Optional: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. Pipeline model</h3><p>A stream is a one-use pipeline over a source, not a collection. Intermediate operations are lazy; a terminal operation drives traversal.</p><p>Avoid mutating the source or shared state from pipeline functions.</p></article><article class="concept-block"><h3>2. Transform and reduce</h3><p>filter keeps elements; map transforms one-to-one; flatMap flattens nested results. collect builds mutable result containers; reduce combines values with an associative rule.</p><p>For parallel-safe reduction, identity, accumulator and combiner must agree. Do not use parallel streams by reflex.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Operation</th><th>Role</th><th>Result</th></tr></thead><tbody><tr><td>filter</td><td>Select</td><td>Stream&lt;T&gt;</td></tr><tr><td>map</td><td>Transform</td><td>Stream&lt;R&gt;</td></tr><tr><td>flatMap</td><td>Transform and flatten</td><td>Stream&lt;R&gt;</td></tr><tr><td>collect</td><td>Mutable reduction</td><td>Collection/map</td></tr><tr><td>reduce</td><td>Value reduction</td><td>Value/Optional</td></tr></tbody></table></div></article><article class="concept-block"><h3>3. Optional discipline</h3><p>Optional represents a possibly absent return value. Transform it with map/flatMap and choose eager or lazy fallback deliberately.</p><p><code>orElse</code> evaluates its fallback immediately; <code>orElseGet</code> invokes a Supplier only when empty. Optional is usually not appropriate for fields, method parameters or collections.</p><div class="concept-note"><strong>Important:</strong> Return an empty collection instead of Optional&lt;List&lt;T&gt;&gt; when absence and an empty result mean the same thing.</div></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Group passing students</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>import java.util.*;import java.util.stream.*;
public class Program {
    record Student(String branch,int mark){}
    public static void main(String[] args){
        var data=List.of(new Student(&quot;CSE&quot;,82),new Student(&quot;ECE&quot;,74),new Student(&quot;CSE&quot;,91));
        var grouped=data.stream().filter(s-&gt;s.mark()&gt;=75).collect(Collectors.groupingBy(Student::branch,Collectors.counting()));
        System.out.println(grouped);
    }
}</code></pre></div><footer>The pipeline filters once and uses a downstream collector to count each branch.<pre>Output:
{CSE=2}</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Lazy Optional fallback</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>import java.util.*;
public class Program {
    static String fallback(){System.out.println(&quot;fallback built&quot;);return &quot;guest&quot;;}
    public static void main(String[] args){Optional&lt;String&gt; name=Optional.of(&quot;Asha&quot;);System.out.println(name.orElseGet(Program::fallback));}
}</code></pre></div><footer>Because the Optional is present, the Supplier is never invoked.<pre>Output:
Asha</pre></footer></article></section><section class="lesson-section" id="trace"><header class="section-heading"><span>INTERACTIVE LEARNING · PROGRAM TRACE</span><h2>Trace lazy stream execution</h2><p>Nothing traverses until the terminal operation requests values.</p></header><div class="visualizer"><div class="trace-code"><header>JAVA EXECUTION</header><div class="trace-lines" id="traceLines"><div class="trace-line" data-line="1"><b>1</b><span>stream source [1,2,3,4]</span></div><div class="trace-line" data-line="2"><b>2</b><span>filter even</span></div><div class="trace-line" data-line="3"><b>3</b><span>map x*x</span></div><div class="trace-line" data-line="4"><b>4</b><span>findFirst</span></div><div class="trace-line" data-line="5"><b>5</b><span>source emits 1</span></div><div class="trace-line" data-line="6"><b>6</b><span>source emits 2</span></div><div class="trace-line" data-line="7"><b>7</b><span>return 4; flatMap flattens.</div><div><b>04</b> Reductions require sound algebraic rules.</div><div><b>05</b> Avoid shared mutation.</div><div><b>06</b> orElseGet is lazy.</div></div></section><section class="lesson-section" id="interview"><header class="section-heading"><span>INTERVIEW QUESTIONS</span><h2>Explain, Do Not Memorize</h2><p>Open each answer only after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. Collection versus Stream?</summary><p>A collection stores elements; a stream describes a one-use computation over a source.</p></details><details><summary>2. Why are intermediates lazy?</summary><p>Laziness enables fusion and short-circuiting so elements flow through stages only as demanded.</p></details><details><summary>3. map versus flatMap?</summary><p>map yields one result per input; flatMap yields nested streams and flattens them into one stream.</p></details><details><summary>4. orElse versus orElseGet?</summary><p>orElse evaluates its value eagerly; orElseGet invokes a supplier only when absent.</p></details><details><summary>5. When avoid parallelStream?</summary><p>For small work, blocking operations, order-sensitive logic or pipelines with shared mutation; overhead and correctness risks may dominate.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
