OBJECT-ORIENTED DESIGN · LEVEL 09</p><h1>Classes &amp; Objects</h1><p class="lead">Model domain state and behaviour with invariants, object identity and clear collaboration boundaries.</p><div class="lesson-meta"><span>Level 9 of 24</span><span>Intermediate</span><span>110–150 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Design cohesive objects that protect valid state</h2><ul><li>Distinguish class, object and reference.</li><li>Define fields and methods.</li><li>Preserve invariants.</li><li>Understand identity and null.</li><li>Model small collaborations.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#trace">Trace</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Classes &amp; Objects: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. Type, object and reference</h3><p>A class defines a type; an object is a runtime instance; a variable holds a reference or null. Several references may identify one object.</p><p>Identity asks whether two references reach the same object. Value equality is a separate domain decision implemented later with equals.</p></article><article class="concept-block"><h3>2. State, behaviour and invariants</h3><p>Fields represent state that persists between calls. Methods should move the object between valid states while preserving invariants.</p><p>Avoid public mutable fields: they let callers bypass validation and couple code to representation.</p><div class="concept-note"><strong>Important:</strong> Place behaviour near the state whose rules it protects.</div></article><article class="concept-block"><h3>3. Collaboration and null</h3><p>Objects collaborate by invoking methods and passing references. Prefer dependencies that express a required role rather than global state.</p><p>Null represents absence but offers no behaviour. Validate required collaborators at construction and use explicit alternatives for meaningful optional results.</p></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Invariant-preserving bank account</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    static final class Account{
        private final String id;
        private long balance;
        Account(String id){if(id==null||id.isBlank())throw new IllegalArgumentException();this.id=id;}
        void deposit(long amount){if(amount&lt;=0)throw new IllegalArgumentException();balance+=amount;}
        boolean withdraw(long amount){if(amount&lt;=0||amount&gt;balance)return false;balance-=amount;return true;}
        long balance(){return balance;}
    }
    public static void main(String[] args){Account a=new Account(&quot;A1&quot;);a.deposit(500);a.withdraw(120);System.out.println(a.balance());}
}</code></pre></div><footer>Clients cannot assign balance directly; every state transition enforces the account policy.<pre>Output:
380</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Shared identity</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    static class Counter{int value;void increment(){value++;}}
    public static void main(String[] args){
        Counter first=new Counter();
        Counter alias=first;
        alias.increment();
        System.out.println(first.value);
    }
}</code></pre></div><footer>Both variables hold the same reference, so the mutation is visible through either name.<pre>Output:
1</pre></footer></article></section><section class="lesson-section" id="trace"><header class="section-heading"><span>INTERACTIVE LEARNING · PROGRAM TRACE</span><h2>Trace object references</h2><p>Separate variables from heap objects.</p></header><div class="visualizer"><div class="trace-code"><header>JAVA EXECUTION</header><div class="trace-lines" id="traceLines"><div class="trace-line" data-line="1"><b>1</b><span>Account a = new Account();</span></div><div class="trace-line" data-line="2"><b>2</b><span>Account b = a;</span></div><div class="trace-line" data-line="3"><b>3</b><span>b.deposit(100);</span></div><div class="trace-line" data-line="4"><b>4</b><span>a = new Account();</span></div><div class="trace-line" data-line="5"><b>5</b><span>print(a.balance, b.balance);</span></div></div></div><div class="trace-state"><header>VISIBLE RUNTIME STATE</header><div class="trace-stage"><span id="traceCounter">READY</span><h3 id="traceTitle">Start the trace</h3><p id="traceText">Move line by line and connect the Java statement to its runtime effect.</p><div class="state-box" id="traceState">No state change yet.</div></div><div class="trace-controls"><button id="traceNext">Next step →</button><button id="traceAuto">▶ Auto run</button><button id="traceReset">Reset</button></div></div></div></section><section class="lesson-section" id="revision"><header class="section-heading"><span>QUICK REVISION</span><h2>Recall the Essential Ideas</h2></header><div class="revision-grid"><div><b>01</b> A class defines a type; an object is an instance.</div><div><b>02</b> Variables hold references, not embedded objects.</div><div><b>03</b> Several references can alias one object.</div><div><b>04</b> Methods should preserve invariants.</div><div><b>05</b> Private fields protect representation.</div><div><b>06</b> Null has no callable behaviour.</div></div></section><section class="lesson-section" id="interview"><header class="section-heading"><span>INTERVIEW QUESTIONS</span><h2>Explain, Do Not Memorize</h2><p>Open each answer only after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. Class versus object?</summary><p>A class declares structure and behaviour; an object is a runtime instance with its own identity and field state.</p></details><details><summary>2. What is an invariant?</summary><p>A condition that must remain true for every externally observable valid object state.</p></details><details><summary>3. Identity versus equality?</summary><p>Identity means the same object; equality means equivalent domain value according to a contract.</p></details><details><summary>4. Why avoid public fields?</summary><p>They expose representation and let callers bypass validation, making future change risky.</p></details><details><summary>5. What happens when a reference is reassigned?</summary><p>Only that variable changes. The previous object remains reachable through other references or becomes GC-eligible.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
