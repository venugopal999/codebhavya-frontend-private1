02

REPEAT FOR EACH TOPIC

A simple study routine

  1. Read for meaning

    Identify the problem, the input and the required output. Read the explanation before memorising syntax. If a term is unfamiliar, review the “Before you start” links below the lesson.

  2. Predict before you run

    Choose a small input and write down the expected output. For a loop, track the counter and one changing variable. A prediction gives you something concrete to compare with the result.

  3. Trace one step at a time

    Where a tracer or visualisation is available, move through a few steps and explain each change. Pause when a condition changes the path. If there is no tracer, make a small table on paper with the same variable names.

  4. Write without looking

    Close or move away from the solution and build your own version. If you get stuck, reread only the part that explains the missing idea, then try again.

  5. Test and explain

    Try a normal input and a boundary case. Compare the result with your prediction. Explain why the algorithm works, what can go wrong, and how its time and space use grow.

  6. Continue with a purpose

    Use “Practise this” to apply the concept or “Learn next” to continue. Before leaving, write one sentence about what you learned and one question you still have.

Example: learning a prime-number program

Predict the answers for 1, 2, 9 and 13. Trace the divisor checks for 9 and 13. Explain why 1 is not prime and why testing factors only up to the square root is sufficient. Then write the program yourself and compare your results.

03

UNDERSTAND THE EXPERIMENT

Use lab solutions as a learning aid

Before writing the code

  • Read the aim and identify the operations you must implement.
  • Follow the algorithm and flowchart. Check what each decision means and where the loop returns.
  • Walk through one sample input by hand.
  • List any input limits or assumptions stated in the solution.

Before calling it finished

  • Run your own implementation and compare the sample output.
  • Test relevant boundaries: empty input where permitted, one element, duplicates, a missing value or an invalid operation.
  • Read the common mistakes and the explanation of complexity.
  • Answer the viva questions aloud before revealing the answers.

For viva preparation

Do more than repeat the answer. Point to the statement in the program that uses the concept. Explain why it is needed and what would happen if it changed. For a stack, for example, connect “last in, first out” to the element removed by a pop operation.

05

TURN A MISTAKE INTO THE NEXT STEP

When you get stuck

The program runs, but the answer is wrong

Reduce the input to the smallest case that still fails. Compare the expected and actual result, then trace the first variable that becomes incorrect. Recheck loop boundaries, arithmetic types and the conditions that choose a branch.

I can follow the solution but cannot write it myself

Write the steps in plain language first. Implement just one operation, test it, and add the next. Afterwards, practise the same idea with different input so you are recalling the method rather than copying the sample.

A link, explanation or sample output seems incorrect

Use “Report an issue” below the learning content. The email draft includes the page address. Describe the section, input or steps, expected result and actual result. Send the email yourself after checking the draft. If an email app does not open, use the Contact page.

How do I know I am ready for the next topic?

Try explaining the concept without reading the page. Solve a small variation, test a boundary case and answer a related viva question. If one part is still unclear, revisit that part before moving on.
