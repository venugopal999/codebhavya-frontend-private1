CORE LIBRARIES · LEVEL 20</p><h1>Multithreading &amp; Concurrency</h1><p class="lead">Reason about shared mutable state using happens-before relationships, task executors and thread-safe designs.</p><div class="lesson-meta"><span>Level 20 of 24</span><span>Advanced</span><span>150–210 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Write concurrency code with explicit safety and lifecycle</h2><ul><li>Distinguish concurrency and parallelism.</li><li>Recognize races and visibility defects.</li><li>Use synchronized, locks and atomics.</li><li>Manage tasks with executors.</li><li>Design cancellation and shutdown.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#trace">Trace</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Multithreading &amp; Concurrency: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. Safety: atomicity and visibility</h3><p>A data race exists when threads access shared mutable state without a sufficient happens-before relationship and at least one access writes. <code>count++</code> is a read-modify-write sequence, not atomic.</p><p>Synchronization, volatile handoff, thread start/join and concurrent utilities establish defined visibility relationships.</p></article><article class="concept-block"><h3>2. Choose the mechanism</h3><p><code>synchronized</code> provides mutual exclusion and visibility around one monitor. volatile provides visibility and ordering for a variable but not compound-operation atomicity. Atomic classes perform lock-free single-variable updates.</p><p>Protect every access to an invariant with the same policy; a lock is useful only when all participants obey it.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Need</th><th>Tool</th><th>Caution</th></tr></thead><tbody><tr><td>Compound invariant</td><td>synchronized/Lock</td><td>Keep critical section focused</td></tr><tr><td>Status flag</td><td>volatile</td><td>No compound atomicity</td></tr><tr><td>Counter</td><td>AtomicLong</td><td>One-variable rules</td></tr><tr><td>Task lifecycle</td><td>ExecutorService</td><td>Shutdown explicitly</td></tr><tr><td>Producer/consumer</td><td>BlockingQueue</td><td>Define backpressure</td></tr></tbody></table></div></article><article class="concept-block"><h3>3. Tasks, cancellation and structure</h3><p>Submit tasks to a bounded executor rather than creating an unbounded thread per request. Futures communicate completion, values and failure.</p><p>Interruption is a cooperative cancellation request. Blocking methods may throw InterruptedException; restore the interrupt when a layer cannot handle it.</p><div class="concept-note"><strong>Important:</strong> Never hold an unrelated lock while performing slow network or file I/O.</div></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Atomic counter</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>import java.util.concurrent.*;import java.util.concurrent.atomic.AtomicInteger;
public class Program {
    public static void main(String[] args) throws Exception{
        AtomicInteger count=new AtomicInteger();
        ExecutorService pool=Executors.newFixedThreadPool(4);
        for(int i=0;i&lt;1000;i++)pool.submit(count::incrementAndGet);
        pool.shutdown();pool.awaitTermination(5,TimeUnit.SECONDS);
        System.out.println(count.get());
    }
}</code></pre></div><footer>AtomicInteger prevents lost updates, and the program owns and terminates its executor.<pre>Output:
1000</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Producer-consumer handoff</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>import java.util.concurrent.*;
public class Program {
    public static void main(String[] args) throws Exception{
        BlockingQueue&lt;String&gt; q=new ArrayBlockingQueue&lt;&gt;(2);
        Thread worker=new Thread(()-&gt;{try{System.out.println(q.take());}catch(InterruptedException e){Thread.currentThread().interrupt();}});
        worker.start();q.put(&quot;job-1&quot;);worker.join();
    }
}</code></pre></div><footer>The bounded queue supplies thread-safe handoff and backpressure; interruption is preserved.<pre>Output:
job-1</pre></footer></article></section><section class="lesson-section" id="trace"><header class="section-heading"><span>INTERACTIVE LEARNING · PROGRAM TRACE</span><h2>Trace a lost update</h2><p>Two individually valid threads can overwrite each other&#39;s increment.</p></header><div class="visualizer"><div class="trace-code"><header>JAVA EXECUTION</header><div class="trace-lines" id="traceLines"><div class="trace-line" data-line="1"><b>1</b><span>count = 0</span></div><div class="trace-line" data-line="2"><b>2</b><span>T1 reads count → 0</span></div><div class="trace-line" data-line="3"><b>3</b><span>T2 reads count → 0</span></div><div class="trace-line" data-line="4"><b>4</b><span>T1 computes and writes 1</span></div><div class="trace-line" data-line="5"><b>5</b><span>T2 computes and writes 1</span></div><div class="trace-line" data-line="6"><b>6</b><span>expected 2; Concurrency versus parallelism?</summary><p>Concurrency manages overlapping tasks; parallelism executes work simultaneously on multiple cores. One can exist without the other.</p></details><details><summary>2. What does volatile guarantee?</summary><p>Visibility and ordering for reads/writes of that variable, not atomicity of multi-step updates or multi-field invariants.</p></details><details><summary>3. What is deadlock?</summary><p>Threads wait cyclically for resources held by one another. Consistent lock ordering and reduced lock scope help prevent it.</p></details><details><summary>4. Why use ExecutorService?</summary><p>It separates tasks from thread creation, bounds resources and provides lifecycle and Future handling.</p></details><details><summary>5. How handle InterruptedException?</summary><p>Perform the layer&#39;s cancellation/cleanup policy; if not consuming it, restore interrupt status before returning or translating.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler.
