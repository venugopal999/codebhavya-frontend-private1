Conditions and guard clauses</h3><p>An <code>if</code> selects work from a boolean result. A guard clause handles invalid or exceptional input early, leaving the main path less deeply nested.</p><p>Name complex business facts with boolean variables; readable conditions are easier to test than dense expressions.</p><ul><li>Test lower and upper boundaries.</li><li>Order exceptional cases before general cases.</li><li>Use braces consistently.</li></ul></article><article class="concept-block"><h3>2. else-if and exhaustive ranges</h3><p>An else-if chain selects its first true branch, so order matters when predicates overlap. Define ranges so every valid input belongs to exactly one branch.</p><p>The final else should express a known remaining case or report invalid data, not hide a missing rule.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Shape</th><th>Best fit</th><th>Main risk</th></tr></thead><tbody><tr><td>if</td><td>Independent action</td><td>Repeated work</td></tr><tr><td>if/else</td><td>Two outcomes</td><td>Reversed condition</td></tr><tr><td>else-if</td><td>Ordered ranges</td><td>Gaps or overlap</td></tr><tr><td>switch</td><td>Discrete labels</td><td>Unclear default</td></tr></tbody></table></div></article><article class="concept-block"><h3>3. Modern switch</h3><p>Arrow cases prevent accidental fall-through. A switch expression yields a value, keeping the decision and assignment together.</p><p>Use <code>yield</code> inside a block branch and define a deliberate default policy.</p><div class="concept-note"><strong>Important:</strong> Use if for ranges and compound predicates; switch for one selector with discrete values.</div></article><article class="concept-block"><h3>4. Decision testing</h3><p>Test one value inside every branch, each boundary, and values immediately outside the valid domain.</p><p>A decision table exposes unhandled combinations when several independent rules interact.</p></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Classify a verified mark</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    static String grade(int mark) {
        if (mark &lt; 0 || mark &gt; 100) return &quot;INVALID&quot;;
        if (mark &gt;= 90) return &quot;A&quot;;
        if (mark &gt;= 75) return &quot;B&quot;;
        if (mark &gt;= 60) return &quot;C&quot;;
        return &quot;D&quot;;
    }
    public static void main(String[] args) {
        System.out.println(grade(75));
    }
}</code></pre></div><footer>Rejecting invalid data first lets descending thresholds describe all remaining ranges without overlap.<pre>Output:
B</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Use a switch expression</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    public static void main(String[] args) {
        String role = &quot;EDITOR&quot;;
        int access = switch (role) {
            case &quot;ADMIN&quot; -&gt; 3;
            case &quot;EDITOR&quot; -&gt; 2;
            case &quot;VIEWER&quot; -&gt; 1;
            default -&gt; 0;
        };
        System.out.println(access);
    }
}</code></pre></div><footer>Each label yields one value, no case falls through, and unknown roles have an explicit policy.<pre>Output:
2</pre></footer></article></section><section class="lesson-section" id="trace"><header class="section-heading"><span>INTERACTIVE LEARNING · PROGRAM TRACE</span><h2>Trace an ordered grade decision</h2><p>Only the first true branch executes.</p></header><div class="visualizer"><div class="trace-code"><header>JAVA EXECUTION</header><div class="trace-lines" id="traceLines"><div class="trace-line" data-line="1"><b>1</b><span>int mark = 75;</span></div><div class="trace-line" data-line="2"><b>2</b><span>if (mark &lt; When is switch preferable to if?</summary><p>When one selector is compared with discrete constants or enum values. If is clearer for ranges and unrelated predicates.</p></details><details><summary>2. What is fall-through?</summary><p>Traditional colon-style cases continue into later cases unless interrupted. Arrow-style cases do not.</p></details><details><summary>3. Why use guard clauses?</summary><p>They reject invalid state early and keep the normal algorithm readable.</p></details><details><summary>4. How should a range be tested?</summary><p>Test every boundary, the values immediately beside it, and one value inside each branch.</p></details><details><summary>5. Can switch return a value?</summary><p>Yes. A switch expression uses arrow results or yield and must cover all outcomes.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler. class="quiz-card"><summary>Good branch tests include:</summary><ol><li>Only typical values</li><li>Boundaries and adjacent values</li><li>Only zero</li><li>Compilation</li></ol><p><strong>Answer:
