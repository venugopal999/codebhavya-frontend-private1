concept-section"><div class="concept-heading"><div class="concept-number">01</div><div><p class="section-label">CONCEPT 01</p><h2>What are we actually learning?</h2></div></div><p class="concept-intro">HTML is not simply a way to make text appear on a page. It describes the structure and meaning of a document.</p><ul class="content-points"><li>Structure comes before visual styling.</li><li>Meaningful elements are easier to understand and maintain.</li><li>Accessibility starts with correct native HTML semantics.</li></ul><div class="explanation-list"><p>A browser can display a page even when the HTML is poorly structured, but a page that merely looks correct is not necessarily a well-designed document.</p><p>Semantic HTML means choosing elements according to the meaning and purpose of their content or interaction rather than choosing elements only for visual appearance.</p><p>Good HTML gives the browser, assistive technologies, developers and other tools a clearer model of what the page contains.</p></div><div class="key-idea"><span>💡</span><div><strong>Key Idea</strong><p>Do not ask only, &#39;How can I make this look like a button?&#39; Ask, &#39;What is this thing supposed to mean or do?&#39;</p></div></div></section><section class="lesson-section concept-section"><div class="concept-heading"><div class="concept-number">02</div><div><p class="section-label">CONCEPT 02</p><h2>HTML Element, Tag and Attribute</h2></div></div><p class="concept-intro">Before learning semantic elements, you must understand the basic parts of HTML markup.</p><div class="explanation-list"><p>An element is the complete HTML node. A normal element can contain an opening tag, content and a closing tag.</p><p>An attribute provides additional information about an element. class="interview-item"><summary><span>01</span>What is semantic HTML?</summary><div class="interview-answer"><p>Semantic HTML means choosing HTML elements according to the meaning and purpose of their content or interaction rather than choosing elements only for visual appearance. Examples include main, nav, article, section, button and footer.</p></div></details><details class="interview-item"><summary><span>02</span>Why is semantic HTML important?</summary><div class="interview-answer"><p>It improves document structure, accessibility, maintainability and machine understanding. A button performs an action such as opening a menu, submitting a form or copying content.</p></div></details><details class="interview-item"><summary><span>06</span>Why should we not use headings only for their visual size?</summary><div class="interview-answer"><p>Heading levels communicate document hierarchy. Visual appearance should be controlled with CSS.</p></div></details><details class="interview-item"><summary><span>07</span>What is the DOM?</summary><div class="interview-answer"><p>The DOM, or Document Object Model, is the browser&#39;s structured in-memory representation of the parsed document. JavaScript and browser APIs can interact with it.</p></div></details><details class="interview-item"><summary><span>08</span>What is the purpose of alt text?</summary><div class="interview-answer"><p>Alt text provides an alternative representation of an image&#39;s useful meaning when the image cannot be perceived. Decorative images can generally use an empty alt attribute.</p></div></details><details class="interview-item"><summary><span>09</span>Why is a div with role=button usually inferior to a native button?</summary><div class="interview-answer"><p>The native button already provides appropriate semantics and browser interaction behavior. A custom role does not automatically recreate all expected keyboard and interaction behavior.</p></div></details><details class="interview-item"><summary><span>10</span>Can a page contain more than one nav element?</summary><div class="interview-answer"><p>Yes. A page may contain multiple meaningful navigation regions, such as primary navigation and course navigation. Appropriate labels can distinguish them when necessary.</p></div></details><details class="interview-item"><summary><span>11</span>Does semantic HTML guarantee good SEO?</summary><div class="interview-answer"><p>No. Semantic HTML helps search engines understand document structure, but SEO depends on many factors including content quality, accessibility, performance, links and technical implementation.</p></div></details><details class="interview-item"><summary><span>12</span>Why should tables not be used for page layout?</summary><div class="interview-answer"><p>Tables are designed to represent relationships among tabular data. Page layout should normally be handled with CSS layout systems rather than table markup.</p></div></details></div></section><section class="lesson-section practice-section"><p class="section-label">PRACTICE ARENA</p><h2>Now apply what you learned</h2><p class="section-description">Try these problems without immediately looking at the solution. the structural language used to describe web documents.</p></article><article><strong>Semantic HTML</strong><p>HTML that communicates the meaning and purpose of content through appropriate elements.</p></article><article><strong>Element</strong><p>A complete HTML node consisting of markup and its content where applicable.</p></article><article><strong>Tag</strong><p>Markup syntax used to identify an HTML element.</p></article><article><strong>Attribute</strong><p>Additional information supplied on an HTML element.</p></article><article><strong>Landmark</strong><p>A major region of a page that helps users and assistive technologies navigate.</p></article><article><strong>DOM</strong><p>The browser&#39;s structured in-memory representation of the parsed HTML document.</p></article><article><strong>Accessibility</strong><p>Designing interfaces so people with different abilities and interaction methods can use them.</p></article><article><strong>ARIA</strong><p>Accessible Rich Internet Applications; a set of accessibility semantics for dynamic or custom interfaces.</p></article><article><strong>Heading hierarchy</strong><p>The structural relationship between h1, h2, h3 and deeper heading levels.</p></article><article><strong>Alternative text</strong><p>Text that communicates the useful meaning of an image when the image itself cannot be perceived.</p></article><article><strong>Tabular data</strong><p>Data organized into rows and columns with meaningful relationships.</p></article><article><strong>Native control</strong><p>A built-in HTML control such as button, input or select that already provides standard browser behavior.</p></article><article><strong>Source order</strong><p>The order in which elements appear in the document source and underlying structure.</p></article><article><strong>Self-contained composition</strong><p>Content that can potentially stand independently, such as an article.</p></article><article><strong>Thematic grouping</strong><p>Related content organized around a meaningful topic, commonly represented by section.</p></article></div></section><section class="lesson-section completion-section"><p class="section-label">LEVEL COMPLETE</p><h2>You now understand the structure beneath the interface</h2><p>Before moving to CSS and advanced frontend development, you should be able to look at an HTML page and explain what every major region means, why each element was selected and how the browser turns the document into a DOM tree.</p><button class="complete-button" id="completeLevel" type="button">Mark Level 2 complete</button></section><nav class="lesson-nav"><a href="lesson.html?level=1">← Previous level</a><a href="lesson.html?level=3">Next level →</a></nav><noscript><p>Lesson reading is available without JavaScript.
