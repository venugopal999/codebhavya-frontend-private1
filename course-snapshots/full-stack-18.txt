class="concept-heading"><div class="concept-number">01</div><div><p class="section-label">CONCEPT 01</p><h2>Rendering Is Not the Same as Updating the DOM</h2></div></div><p class="concept-intro">One like.</li><li>React can render a component without changing every corresponding DOM node.</li><li>After rendering, React compares the new result with the previous result and commits only the necessary DOM changes.</li><li>Therefore, saying &#39;the component rendered&#39; does not automatically mean &#39;the browser rebuilt everything&#39;.</li></ul><div class="key-idea"><span>💡</span><div><strong>Key Idea</strong><p>A React render is a calculation. class="lesson-section revision-section"><p class="section-label">QUICK REVISION</p><h2>Remember these essential ideas</h2><div class="revision-grid"><article><b>01</b><div><strong>Render</strong><p>React calculates the next UI representation.</p></div></article><article><b>02</b><div><strong>Re-render</strong><p>A component is evaluated again because its state, parent, props, context or another subscribed source changed.</p></div></article><article><b>03</b><div><strong>React.memo</strong><p>Can skip a child render when change.</p></div></article><article><b>05</b><div><strong>useCallback</strong><p>Caches a function reference until dependencies change.</p></div></article><article><b>06</b><div><strong>Referential class="lesson-section interview-section"><p class="section-label">PLACEMENT & INTERVIEW</p><h2>Explain the concept, don't just memorize it</h2><div class="interview-list"><details class="interview-item"><summary><span>01</span>What causes a React component to re-render?</summary><div class="interview-answer"><p>Common causes include its own state changing, receiving changed props, a parent rendering, or subscribed context/external state changing.</p></div></details><details class="interview-item"><summary><span>02</span>Does a React re-render mean the whole DOM is rebuilt?</summary><div class="interview-answer"><p>No. Rendering calculates the next UI result. React then compares it with the previous result and commits only the necessary DOM changes.</p></div></details><details class="interview-item"><summary><span>03</span>What is React.memo?</summary><div class="interview-answer"><p>React.memo creates a memoized component that can skip rendering when its props are considered equal.</p></div></details><details class="interview-item"><summary><span>04</span>What is the difference between useMemo and useCallback?</summary><div class="interview-answer"><p>useMemo memoizes a calculated value. useCallback memoizes a function reference.</p></div></details><details class="interview-item"><summary><span>05</span>Why can an object prop defeat React.memo?</summary><div class="interview-answer"><p>A newly created object has a new reference even when its contents are identical, so shallow comparison can consider the prop changed.</p></div></details><details class="interview-item"><summary><span>06</span>Why should array indexes sometimes be avoided as keys?</summary><div class="interview-answer"><p>When items are inserted, removed or reordered, an index can point to a different logical item and cause incorrect component identity.</p></div></details><details class="interview-item"><summary><span>07</span>When should you use useMemo?</summary><div class="interview-answer"><p>When caching a derived calculation provides a meaningful performance benefit and the dependencies are well defined.</p></div></details><details class="interview-item"><summary><span>08</span>What is the purpose of React Testing Library?</summary><div class="interview-answer"><p>It provides utilities for testing React interfaces through user-observable behaviour and accessible interactions.</p></div></details><details class="interview-item"><summary><span>09</span>Why test loading and error states?</summary><div class="interview-answer"><p>Because production applications do not only have successful responses. Users also experience loading, empty and failure states.</p></div></details><details class="interview-item"><summary><span>10</span>Should every React component use React.memo?</summary><div class="interview-answer"><p>No. Memoization is an optimization. It should be applied where measurements and component behaviour indicate that skipping work is useful.</p></div></details></div></section><section class="lesson-section practice-section"><p class="section-label">PRACTICE ARENA</p><h2>Now apply what you learned</h2><p class="section-description">Try these problems without immediately looking at the solution.
