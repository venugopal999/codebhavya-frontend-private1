OBJECT-ORIENTED DESIGN · LEVEL 10</p><h1>Constructors, this &amp; static</h1><p class="lead">Establish valid objects at construction time and separate instance ownership from class-wide state.</p><div class="lesson-meta"><span>Level 10 of 24</span><span>Intermediate</span><span>110–150 minutes</span><span>8 concept checks</span></div></div><aside class="outcome-card"><span>BY THE END, YOU CAN</span><h2>Initialize objects with explicit ownership rules</h2><ul><li>Design constructor invariants.</li><li>Chain constructors.</li><li>Use this without confusion.</li><li>Separate static and instance members.</li><li>Create immutable value objects.</li></ul></aside></section><nav class="jump-bar"><a href="#concepts">Concepts</a><a href="#examples">Examples</a><a href="#revision">Revision</a><a href="#interview">Interview</a><a href="#practice">Practice</a><a href="#quiz">Check</a></nav><section class="lesson-section" id="concepts"><header class="section-heading"><span>CONCEPTS · MECHANISMS · TRADE-OFFS</span><h2>Constructors, this &amp; static: Mental Models and Practice</h2><p>Learn the mechanism first, then use the API with clear assumptions, boundaries and tests.</p></header><article class="concept-block"><h3>1. Construction and chaining</h3><p>A constructor initializes a new object and has no return type. Validate required state before exposing the object.</p><p><code>this(...)</code> delegates to another constructor and must be the first statement, centralizing defaults and validation.</p></article><article class="concept-block"><h3>2. Meaning of this</h3><p><code>this</code> is the current receiver. It disambiguates a field from a parameter and can pass or return the current object.</p><p>Do not let <code>this</code> escape during construction; callbacks may observe partially initialized state.</p></article><article class="concept-block"><h3>3. Static ownership</h3><p>Instance members belong to each object. Static members belong to the class and should represent truly shared stateless behaviour or carefully managed class-wide state.</p><p>A static method has no receiver and cannot directly access instance fields.</p><div class="concept-table-wrap"><table class="concept-table"><thead><tr><th>Member</th><th>Owner</th><th>Access</th></tr></thead><tbody><tr><td>instance field</td><td>Each object</td><td>Through a receiver</td></tr><tr><td>instance method</td><td>Receiver object</td><td>Has this</td></tr><tr><td>static field</td><td>Class</td><td>Shared</td></tr><tr><td>static method</td><td>Class</td><td>No this</td></tr></tbody></table></div></article><article class="concept-block"><h3>4. Immutability</h3><p>An immutable object establishes all state during construction, keeps fields private and final, and exposes no mutation path.</p><p>Defensively copy mutable inputs and outputs; final freezes a reference, not the referenced object.</p></article></section><section class="lesson-section" id="examples"><header class="section-heading"><span>RUNNABLE JAVA</span><h2>Examples Worth Tracing</h2><p>Predict the result before running each program. Then change one value and explain the new behaviour.</p></header><article class="example-card"><header><div><span>EXAMPLE 01</span><h3>Immutable money value</h3></div><button class="copy-code" type="button" data-copy-example="0">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    record Money(long paise,String currency){
        Money{if(paise&lt;0||currency==null||currency.isBlank())throw new IllegalArgumentException();}
        Money add(Money other){if(!currency.equals(other.currency))throw new IllegalArgumentException();return new Money(paise+other.paise,currency);}
    }
    public static void main(String[] args){System.out.println(new Money(2500,&quot;INR&quot;).add(new Money(500,&quot;INR&quot;)));}
}</code></pre></div><footer>The compact record constructor enforces invariants and addition returns a new value rather than mutating either operand.<pre>Output:
Money[paise=3000, currency=INR]</pre></footer></article><article class="example-card"><header><div><span>EXAMPLE 02</span><h3>Constructor chaining</h3></div><button class="copy-code" type="button" data-copy-example="1">Copy code</button></header><div class="code-wrap"><pre><code>public class Program {
    static class User{
        final String name;final String role;
        User(String name){this(name,&quot;VIEWER&quot;);}
        User(String name,String role){this.name=name;this.role=role;}
    }
    public static void main(String[] args){System.out.println(new User(&quot;Asha&quot;).role);}
}</code></pre></div><footer>The one-argument constructor delegates the default to the complete constructor.<pre>Output:
VIEWER</pre></footer></article></section><section class="lesson-section" id="revision"><header class="section-heading"><span>QUICK REVISION</span><h2>Recall the Essential Ideas</h2></header><div class="revision-grid"><div><b>01</b> Constructors establish initial validity.</div><div><b>02</b> this refers to the receiver.</div><div><b>03</b> this(...) must be first.</div><div><b>04</b> Static state is shared by the class.</div><div><b>05</b> Static methods have no this.</div><div><b>06</b> final references may still point to mutable objects.</div></div></section><section class="lesson-section" id="interview"><header class="section-heading"><span>INTERVIEW QUESTIONS</span><h2>Explain, Do Not Memorize</h2><p>Open each answer only after speaking your own version aloud.</p></header><div class="interview-list"><details><summary>1. Can a constructor be final?</summary><p>No. Constructors are not inherited or overridden.</p></details><details><summary>2. this versus this()?</summary><p>this is the current receiver; this(...) invokes another constructor in the same class.</p></details><details><summary>3. When is static appropriate?</summary><p>For stateless utility behaviour, constants, factories or genuinely class-wide state with explicit lifecycle and concurrency policy.</p></details><details><summary>4. Does final make an object immutable?</summary><p>No. It prevents reference reassignment; the object may still mutate.</p></details><details><summary>5. Why avoid this escaping from a constructor?</summary><p>Other code or threads could observe the object before all invariants are established.</p></details></div></section><section class="lesson-section" id="practice"><header class="section-heading"><span>PROGRAMMING PROBLEMS</span><h2>Apply the Concept Independently</h2><p>Use the CodeBhavya online compiler. class="quiz-card"><summary>A static field belongs to:</summary><ol><li>The class</li><li>Each call</li><li>One local block</li><li>Only subclass</li></ol><p><strong>Answer: The class</strong> One class-level state is shared.</p></details><details class="quiz-card"><summary>Static method has this?</summary><ol><li>Yes</li><li>No</li><li>Only public</li><li>Only final</li></ol><p><strong>Answer: No</strong> There is no receiver.</p></details><details class="quiz-card"><summary>final reference prevents:</summary><ol><li>Reassignment</li><li>Object should avoid:</summary><ol><li>Exposing mutable internals</li><li>Validation</li><li>final fields</li><li>Value methods</li></ol><p><strong>Answer: Exposing mutable internals</strong> Callers could
